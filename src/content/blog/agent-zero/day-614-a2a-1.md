## 上一课回顾

[Day 612](/blog/agent-zero/day-612-deep-research-1/) 和 [Day 613](/blog/agent-zero/day-613-deep-research-2/) 做了一个研究流水线:主管拆题,几个研究员并行查资料、压缩成笔记,最后写报告,再用规则层和逐句评审查引用。那几个研究员都是你自己写的函数,`research_one(sq, llm, search, budget)`,参数是什么、返回什么、里面怎么查,你全知道。

## 第 1 步:对面是工具,和对面是 Agent,差在哪

先别急着看协议。协议是为了解决问题而生的,先把问题本身看清楚。下面用纯 Python 模拟同一件事的两种对面:一个是查客户的**工具**,一个是别的团队的**对账 Agent**。不联网,不调模型,对账 Agent 里面的逻辑全是写死的,目的只是让你从调用方的角度感受一下区别。

```python
# agent-zero-lab/part10/a2a/tool_vs_agent.py
"""同一件事,对面是「工具」和对面是「Agent」时,调用方看到的东西完全不一样。纯本地模拟,不联网、不调模型。"""
import asyncio
import itertools
from dataclasses import dataclass, field


# ---------- 对面是工具:参数和返回值都写在说明书上,调一次就有结果 ----------
def find_customer(email: str) -> dict[str, str]:
    """按邮箱查客户。参数:email。返回:id、name、plan。"""
    return {"id": "C-0042", "name": "王芳", "plan": "team-y"}


# ---------- 对面是 Agent:你只拿到一个任务,它自己决定怎么做、要不要问你 ----------
@dataclass
class Task:
    id: str
    state: str = "submitted"
    question: str = ""
    result: str = ""
    history: list[str] = field(default_factory=list)


class FinanceAgent:
    """别的团队的对账 Agent。调用方看不到下面的私有方法,只能发消息、看任务状态。"""

    _ids = itertools.count(1)

    def __init__(self) -> None:
        self.tasks: dict[str, Task] = {}
        self._running: set[asyncio.Task[None]] = set()

    def send(self, text: str, task_id: str | None = None) -> Task:
        task = self.tasks[task_id] if task_id else Task(id=f"task-{next(self._ids)}")
        if task.state in ("completed", "failed", "canceled", "rejected"):
            raise ValueError(f"{task.id} 已经是终态 {task.state},不能再发消息")
        self.tasks[task.id] = task
        task.history.append(text)
        if not any("INV-" in h for h in task.history):
            task.state, task.question = "input-required", "请提供发票号(INV- 开头)"
        else:
            task.state, task.question = "working", ""
            job = asyncio.get_running_loop().create_task(self._reconcile(task))
            self._running.add(job)
            job.add_done_callback(self._running.discard)
        return task

    async def _reconcile(self, task: Task) -> None:
        await asyncio.sleep(0.3)  # 假装去查了账、对了合同,真实情况可能是几分钟
        task.state, task.result = "completed", "INV-0042-03 重复扣款 ¥1,200,已发起退款"

    def get(self, task_id: str) -> Task:
        return self.tasks[task_id]


async def main() -> None:
    print("工具:", find_customer("wangfang@example.com"))
    agent = FinanceAgent()
    task = agent.send("客户 C-0042 说上个月被扣了两次钱,帮忙核对")
    print(f"Agent:{task.id} -> {task.state},它问:{task.question}")
    task = agent.send("发票号 INV-0042-03", task_id=task.id)
    print(f"Agent:{task.id} -> {task.state}")
    while task.state == "working":
        await asyncio.sleep(0.1)
        task = agent.get(task.id)
    print(f"Agent:{task.id} -> {task.state},结果:{task.result}")
    try:
        agent.send("再帮我看看 INV-0042-04", task_id=task.id)
    except ValueError as e:
        print("再发一条:", e)


if __name__ == "__main__":
    asyncio.run(main())
```

<div class="line-notes">

- `def find_customer(email: str) -> dict[str, str]:` 工具就是一个函数。参数、返回值、做什么,全写在签名和 docstring 里,这正是 MCP 里一个 tool 的样子([Day 271](/blog/agent-zero/day-271-mcp-why/) 起学的):名字、说明、输入 schema。调用方对它的行为有完全的预期。
- `return {"id": "C-0042", "name": "王芳", "plan": "team-y"}` 调一次,马上有结果,没有中间状态。
- `class Task:` 对面是 Agent 时,你拿到的不是结果,是一个**任务**。它有 id、有状态、可能有一个问你的问题、最后才有结果。
- `state: str = "submitted"` 状态名我照着 A2A 规范里任务状态的意思取:submitted(收到了)、working(在做)、input-required(要你补信息)、completed / failed / canceled / rejected(四种终态)。规范里的确切拼写和完整列表 Day 616 再读,今天先感受它为什么需要状态。
- `history: list[str] = field(default_factory=list)` 同一个任务里你来我往的消息。多轮交互都挂在同一个任务 id 下面。
- `_ids = itertools.count(1)` 一个从 1 开始数的计数器,`next(self._ids)` 每调一次给下一个数。类属性,所有实例共用,保证任务 id 不重复。
- `self._running: set[asyncio.Task[None]] = set()` 保存后台在跑的协程任务。为什么要存,下面 `create_task` 那行讲。
- `task = self.tasks[task_id] if task_id else Task(id=f"task-{next(self._ids)}")` 带了 task_id 就是接着之前的任务说,没带就开一个新任务。
- `if task.state in ("completed", "failed", "canceled", "rejected"):` **终态不能再动**。任务完成了你再往里发消息,对方应该拒绝,而不是悄悄又开工。A2A 规范对终态任务的要求也是这样。
- `if not any("INV-" in h for h in task.history):` 对方自己判断信息够不够:翻遍这个任务的所有消息都没有发票号,就反过来问你。这个判断在对方内部,你看不到,也不该看到。
- `task.state, task.question = "input-required", "请提供发票号(INV- 开头)"` 不是报错,是一个正常的中间状态:任务还活着,在等你。
- `job = asyncio.get_running_loop().create_task(self._reconcile(task))` 把真正的对账丢到后台跑,`send` 立刻返回一个 working 状态的任务。这就是「长任务」:调用方拿到回执就走,过一会儿再来看。`create_task` 相当于 JS 里不 await 直接调一个 async 函数,让它自己跑。
- `self._running.add(job)` Python 文档专门提醒过:事件循环对 `create_task` 创建的任务只保留弱引用,你不自己存一份,它可能跑到一半被垃圾回收掉。存进集合,跑完时 `add_done_callback(self._running.discard)` 再自动删掉。
- `await asyncio.sleep(0.3)  # 假装去查了账` 模拟对方在干活。真实的对账 Agent 可能要调好几个系统、跑几分钟。
- `while task.state == "working":` 调用方这边只能**轮询**:隔一会儿看一次状态。轮询是最朴素的办法,A2A 还支持流式推送和 webhook 回调,Day 616 讲传输时会看到。
- `agent.send("再帮我看看 INV-0042-04", task_id=task.id)` 往一个已经 completed 的任务里再发消息,应该被拒绝。想再查一张发票,就该开一个新任务。

</div>

五行输出把区别都摆出来了。对工具,你调一次拿结果,完事。对 Agent,你经历了三件工具没有的事:

- **它是不透明的**(opaque)。它要不要发票号、怎么对账、调了哪些系统,你不知道。你只知道它声明过「我能对账」。
- **它有状态,而且可能要跑很久**。你拿到的是一个任务 id,要回来看它到哪一步了。
- **它会反过来问你**。input-required 不是失败,是对话的一部分。同一个任务里可以来回好几轮。

这三件事,用「函数调用」或者 MCP 的「工具调用」都表达不好。MCP 的工具调用默认是一问一答的;你当然可以硬把「对账 Agent」包成一个 MCP 工具,但等它跑五分钟、中途要问你发票号的时候,就很别扭了。这就是 A2A 这类协议要解决的问题。

### 一个顺手踩的坑

`send` 里用了 `asyncio.get_running_loop()`,它要求**当前有一个正在跑的事件循环**。如果你在普通脚本里直接调(不在 `async def` 里、没有 `asyncio.run`),第一次 send 因为缺发票号走的是 input-required 分支,没碰到事件循环,不会报错;第二次带上发票号,就炸了:

```bash
uv run python -c "
from part10.a2a.tool_vs_agent import FinanceAgent
a = FinanceAgent()
t = a.send('客户 C-0042 说被扣了两次钱')
print(t.state)
a.send('发票号 INV-0042-03', task_id=t.id)"
```

```text
input-required
Traceback (most recent call last):
  ...
    job = asyncio.get_running_loop().create_task(self._reconcile(task))
          ^^^^^^^^^^^^^^^^^^^^^^^^^^
RuntimeError: no running event loop
```

这种「第一次不炸、第二次才炸」的错最烦人,因为它取决于走哪个分支。修法就是像 `main()` 那样,把调用放在 `async def` 里,用 `asyncio.run(main())` 启动。真实的 A2A 服务端是一个 Web 服务(Day 616 用的是官方 SDK 起的服务),事件循环由框架管,不会碰到这个问题;但你自己写测试脚本时很容易撞上。

**MCP**(Model Context Protocol)管 Agent 和工具、数据之间。对面是透明的:你知道它有哪些工具、每个工具的参数是什么,调一次通常很快返回。第五部分从 [Day 271](/blog/agent-zero/day-271-mcp-why/) 开始讲了整整一组,你自己写过 CloudLedger 的 MCP server,四个工具 `find_customer`、`get_subscription`、`list_invoices`、`create_refund_request`。MCP 的规范按日期发版,我今天查官方仓库,最新的一版是 2026-07-28(练习 3 会用代码列出所有版本)。

**A2A**(Agent2Agent)管 Agent 和 Agent 之间。关键区别就是第 1 步那三件事:对面不透明,任务有状态、可能跑很久,会反过来问你。A2A 规范把「不透明」写成了一条设计原则(Opaque Execution):Agent 之间基于声明的能力和交换的信息协作,不需要共享内部的思考、计划和工具实现。你和财务团队的对账 Agent 合作,不需要知道它用的是 LangGraph 还是自己写的循环,也不该知道它的提示词。

**ACP** 在 2026 年一般指 **Agent Client Protocol**,管的是编辑器或控制台这类「人用的客户端」和 Coding Agent 之间。你在 [Day 605](/blog/agent-zero/day-605-coding-agents-2/) 见过它:OpenHands 的 Agent Canvas 就是通过 ACP 去跑 Claude Code、Codex 这些第三方 Agent 的。它由做 Zed 编辑器的团队在 2025 年 8 月推出,思路学的是 LSP(Language Server Protocol,前端同学熟悉的那个,VS Code 里 TypeScript 的补全和跳转就是靠它):Agent 实现一次 ACP,就能在所有支持 ACP 的编辑器里用。本地的 Agent 作为编辑器的子进程运行,双方用 JSON-RPC 通过标准输入输出通信,和 MCP 的 stdio 传输([Day 276](/blog/agent-zero/day-276-mcp-transports/))是一个路数。JetBrains 在 2025 年 10 月加入共建,2026 年 1 月给 IDE 加了 ACP 的 Agent 注册表。

**这里有一个必须分清的同名坑**。IBM 在 2025 年 3 月也发过一个协议,叫 Agent **Communication** Protocol,缩写也是 ACP,做的事情和 A2A 很像(Agent 和 Agent 之间)。2025 年 8 月,IBM 和 Google 宣布把它并进 A2A,原来的仓库归档了,IBM 研究院的项目页上现在挂着「ACP is now part of A2A」。所以你在 2025 年上半年的文章里看到「MCP、A2A、ACP 三足鼎立」,那个 ACP 多半是 IBM 那个,已经不存在了;2026 年说的 ACP,基本是 Agent Client Protocol。看资料时先看日期,再看全称。

一句话的判断方法:**对面是「能力确定的函数」,用 MCP;对面是「有自己判断力、可能要和你来回商量的同事」,用 A2A;对面是「坐在编辑器前的人」,用 ACP**。

## 第 2 步:把「该用哪个」写成一个函数

光记一句话还不够,面试和做设计时你会遇到很多边界情况。把判断过程写成代码,逼自己把每个条件想清楚:

```python
# agent-zero-lab/part10/a2a/which_protocol.py
"""把「该用哪个协议」写成一个函数:先问对面是谁,再问是不是同一个团队、会不会跑很久、要不要来回商量。"""
from dataclasses import dataclass
from typing import Literal


@dataclass
class Counterpart:
    name: str
    kind: Literal["tool", "agent", "editor"]  # 对面是工具/数据、别的 Agent、还是人用的编辑器
    same_codebase: bool = False  # 和你的 Agent 在同一个代码库、同一个团队
    long_running: bool = False  # 一次调用可能跑几分钟以上
    multi_turn: bool = False  # 中途可能反过来问你


def which_protocol(c: Counterpart) -> str:
    if c.kind == "editor":
        return "ACP:编辑器连 Coding Agent"
    if c.kind == "tool":
        return "函数调用" if c.same_codebase else "MCP:Agent 连工具和数据"
    if c.same_codebase:
        return "子 Agent / 函数调用:同一个代码库,别为了协议而协议"
    if c.long_running or c.multi_turn:
        return "A2A:对面是看不见内部的 Agent,任务有状态"
    return "A2A 或者当成 MCP 工具:对面是 Agent 但用起来像函数,两种都行"


if __name__ == "__main__":
    cases = [
        Counterpart("CloudLedger 账单库", "tool"),
        Counterpart("本仓库里的 refund_amount()", "tool", same_codebase=True),
        Counterpart("Day 612 的研究员", "agent", same_codebase=True, long_running=True),
        Counterpart("财务团队的对账 Agent", "agent", long_running=True, multi_turn=True),
        Counterpart("供应商的汇率换算 Agent", "agent"),
        Counterpart("Zed 编辑器", "editor"),
    ]
    for c in cases:
        print(f"{c.name:<20} -> {which_protocol(c)}")
```

<div class="line-notes">

- `from typing import Literal` `Literal["tool", "agent", "editor"]` 表示这个字段只能是这三个字符串之一,和 TS 的 `kind: "tool" | "agent" | "editor"` 一模一样。写错了 basedpyright 会画红线,运行时不检查。
- `same_codebase: bool = False  # 和你的 Agent 在同一个代码库、同一个团队` 这是最常被忽略、但最先该问的条件。
- `if c.kind == "editor":` 编辑器那条线和另外两条完全不搭界,先排除掉。
- `return "函数调用" if c.same_codebase else "MCP:Agent 连工具和数据"` 同一个代码库里的工具,直接 import 调用就行。只有跨进程、跨团队、或者想让多个 Agent 复用时,才值得包成 MCP server。
- `if c.same_codebase:` **同一个代码库里的 Agent,哪怕它跑得很久,也用子 Agent 或函数调用**。Day 612 的研究员就是例子:它们是 Agent、要跑一会儿,可它们是你自己的代码,`asyncio.gather` 一行就并行了,套一层 A2A 只会多出网络、序列化和鉴权的麻烦。
- `if c.long_running or c.multi_turn:` 跨团队、又会跑很久或者要来回商量的,才是 A2A 最典型的场景。
- `return "A2A 或者当成 MCP 工具:` 对面是别人的 Agent,但一问一答、很快返回(比如汇率换算),用起来就像个函数。这时两种都行,看对方提供了哪种接口。

</div>

**2025 年**:Google 在 4 月发布 A2A,6 月捐给 Linux 基金会,7 月 30 日发了 0.3 版。8 月,IBM 的 Agent Communication Protocol 并入 A2A(上面那个同名坑)。这一年 A2A 的版本号还在 0.x,改动频繁,早期的教程和代码到现在大多已经对不上了。

**2026 年 3 月 12 日,1.0 发布**。这是第一个稳定版,而且相对 0.3 有不兼容的改动(具体改了什么是 Day 616 的内容)。Linux 基金会 4 月的新闻稿里提到,1.0 加了多协议支持、多租户、更新的安全流程,还有一条给早期用户的迁移路径,以及签名的 Agent Card(Agent 的「名片」,用来证明这张名片确实是它的主人发的,Day 616 细讲)。5 月 28 日发了 1.0.1 修订版。同一篇新闻稿说支持 A2A 的组织超过 150 家,微软和 AWS 都已经把它接进了自己的平台。

**2026 年 8 月 17 日,A2A 加入 AAIF**。AAIF 是 Agentic AI Foundation,Linux 基金会旗下专门管 Agent 相关开源项目的基金会,2025 年 12 月成立,MCP 也在里面。A2A 是它的第五个托管项目。AAIF 的公告把五个项目按层次列了一遍,我觉得这张分层比任何一篇对比文章都清楚:

| 项目 | AAIF 公告里的定位 | 一句话 |
| --- | --- | --- |
| AGENTS.md | 告诉 Agent 这个项目的约定和操作说明 | 给 Agent 看的 README |
| goose | Agent 推理、规划、调用能力、干活的运行环境 | Agent 运行时 |
| MCP | Agent 连接工具、数据源、应用和服务 | Agent 到工具 |
| agentgateway | 在 Agent 系统和底层基础设施的边界上管流量和控制 | 网关 |
| A2A | Agent 和 Agent 之间的互操作层 | Agent 到 Agent |

注意这张表里没有 ACP(Agent Client Protocol),它不在 AAIF,是 Zed 和 JetBrains 在推。所以「三层协议」是我们为了好记做的归纳,不是某个组织的官方分层。

归属这件事为什么重要?一个协议要成为行业标准,技术好只是一方面,另一方面是**没有一家公司能单方面改它**。A2A 从 Google 一家的项目,到 Linux 基金会,再到和 MCP 同一个专门的基金会,治理越来越中立,竞争对手才敢放心跟进。

```python
# agent-zero-lab/part10/a2a/protocol_status.py
"""查三个协议的 Python SDK 现在是什么版本、A2A 规范发过哪些版本。只读公开接口,不需要 key。"""
import httpx

PACKAGES = {"mcp": "MCP", "a2a-sdk": "A2A", "agent-client-protocol": "ACP(Agent Client Protocol)"}


def pypi_latest(client: httpx.Client, name: str) -> tuple[str, str]:
    data = client.get(f"https://pypi.org/pypi/{name}/json").raise_for_status().json()
    version = data["info"]["version"]
    files = data["releases"][version]
    return version, files[0]["upload_time"][:10] if files else "?"


def a2a_spec_releases(client: httpx.Client) -> list[tuple[str, str]]:
    url = "https://api.github.com/repos/a2aproject/A2A/releases?per_page=100"
    rows = client.get(url).raise_for_status().json()
    return [(r["tag_name"], r["published_at"][:10]) for r in rows]


if __name__ == "__main__":
    transport = httpx.HTTPTransport(retries=2)
    with httpx.Client(timeout=20, follow_redirects=True, transport=transport) as client:
        for pkg, proto in PACKAGES.items():
            version, day = pypi_latest(client, pkg)
            print(f"{proto:<28} {pkg:<22} {version:<8} {day}")
        releases = a2a_spec_releases(client)
        if not releases:
            raise SystemExit("GitHub 返回了空列表,过一会儿再跑一次")
        first_tag, first_day = releases[-1]
        print(f"A2A 规范共 {len(releases)} 个 release,列表最后一个是 {first_tag}({first_day}),最近三个:")
        for tag, day in releases[:3]:
            print(f"  {tag:<8} {day}")
```

<div class="line-notes">

- `PACKAGES = {"mcp": "MCP", "a2a-sdk": "A2A", "agent-client-protocol": "ACP(Agent Client Protocol)"}` 三个协议官方 Python SDK 在 PyPI 上的包名。A2A 的包名是 `a2a-sdk`,不是 `a2a`,`pip install a2a` 装到的是别的东西。
- `data = client.get(f"https://pypi.org/pypi/{name}/json").raise_for_status().json()` PyPI 的公开 JSON 接口,你在浏览器里打开 `https://pypi.org/pypi/mcp/json` 也能看到。`raise_for_status()` 在 4xx/5xx 时抛异常,成功时返回响应本身,所以能接着 `.json()` 链式调用,和 `fetch(...).then(r => { if (!r.ok) throw ...; return r.json() })` 是一个意思。
- `version = data["info"]["version"]` 最新的正式版本号。
- `files = data["releases"][version]` 这个版本上传的所有文件(源码包、wheel),取第一个的上传时间当发布日期。
- `url = "https://api.github.com/repos/a2aproject/A2A/releases?per_page=100"` GitHub 的发版列表接口,不登录每小时能调 60 次。A2A 规范仓库在 `a2aproject` 这个组织下,不在 Google 名下,这本身就说明了归属。
- `return [(r["tag_name"], r["published_at"][:10]) for r in rows]` 取版本标签和发布日期。`[:10]` 把 `2026-03-12T...` 截成日期。
- `transport = httpx.HTTPTransport(retries=2)` 连接失败时自动重试两次。这一行是我跑出错以后加的,下面说。
- `if not releases:` GitHub 偶尔会返回一个空列表,不加这个判断,下一行 `releases[-1]` 会抛 `IndexError`。也是跑出来的。
- `first_tag, first_day = releases[-1]` 列表按发布时间倒序,最后一个是最早的。

</div>

几处值得读出来的信息:

- `a2a-sdk` 是 1.2.3,规范是 1.0.1。**SDK 的版本号和规范的版本号是两回事**,SDK 1.2.x 实现的是规范 1.0。别看到 SDK 1.2 就以为规范出到 1.2 了。
- 列表里最早的 v0.1.0 标着 2025-06-09,可 A2A 是 4 月发布的。这是因为 GitHub release 是后来补建的,v0.1.0 到 v0.2.2 好几个都是同一天建的。所以「发布日期」要分清是规范发布、还是仓库里打标签的日期。GitHub 的数据是一手的,但也要会读。
- ACP 的 Python 包还在 0.x,协议仓库最近的 release 号是 v1.12.0(10 月 16 日),可它 README 里专门写了一句:当前稳定的 ACP **协议版本是 `1`**,v1.12.0 是仓库里 Rust 包的版本,双方兼容不兼容看握手时交换的 `protocolVersion`。又一个「版本号不是一回事」的例子。

我第一次跑这个脚本时其实没有那两处防御。第一次,经过本机代理访问 PyPI 时连接被断开:

```text
httpx.ConnectError: [SSL: UNEXPECTED_EOF_WHILE_READING] EOF occurred in violation of protocol (_ssl.c:1010)
```

重跑一次就好了,所以加了 `retries=2`。注意 `HTTPTransport(retries=...)` 只重试**连接阶段**的失败(连不上、TLS 握手断了),不会重试已经拿到的 500 响应,这正好适合这种查询脚本。第二次,GitHub 回了 200,内容却是一个空列表 `[]`,我用 curl 也复现了一次(响应头 `content-length: 2`),过一会儿再查又正常了。没有 `if not releases` 那一行,脚本就在 `releases[-1]` 上抛 `IndexError: list index out of range`。外部接口「返回成功但内容不对」比「直接报错」更难防,写任何调外部接口的代码都要想到它。

## 我对「哪个会成为标准」的看法

这一节是我的判断,不是事实,你可以不同意,但面试时要能讲出自己的判断和依据。

**MCP 在工具层已经赢了。** 主流模型厂商、IDE、框架都支持,企业内部的工具接入基本默认用它。剩下的问题是治理:远程 MCP 的鉴权、工具注册、审计,这是 [Day 589](/blog/agent-zero/day-589-mcp-gw-1/) 和 Day 590 讲过的内容。

**A2A 有了标准的形态,用法还在早期。** 中立治理有了,稳定版有了,大厂在接,这些都是成为标准的必要条件。但就像第 2 步那六个场景,真正非 A2A 不可的场景比宣传的少。我看到的落地集中在两类:大企业跨部门的 Agent 平台,SaaS 厂商把 Agent 能力开放给客户。发现机制(怎么知道有哪些 Agent 可用、去哪找)目前还是 Agent 互联里最不成熟的部分。

**ACP 在编辑器这条线上走得很快**,但它和你写业务 Agent 的关系不大,除非你做的就是 Coding Agent 或开发工具。

**我的建议**:同一个团队的 Agent 之间,用函数调用、子 Agent 或内部 API;跨团队、需要长任务和多轮交互、双方各自独立发版时,用 A2A;要把你的 Agent 开放给外部时,同时提供 MCP(当工具用)和 A2A(当 Agent 用)两种接口,让调用方选。练习 2 会把这条建议写成代码。

## 动手练习

**练习 1:给对账 Agent 加「拒绝」和「取消」。** 第 1 步的 `FinanceAgent` 只会走到 completed。写一个子类 `FinanceAgentV2`:发票号以 `INV-9` 开头时直接 rejected(假设那些发票不归这个客户);再加一个 `cancel(task_id)`,能取消还没完成的任务,对已经是终态的任务报错。写一个调用方,分别跑出 completed、rejected、canceled 三种结局。

<details><summary>参考答案</summary>

```python
# agent-zero-lab/part10/a2a/ex614_cancel.py
"""练习 1:给对账 Agent 加「取消」和「拒绝」两条路,调用方要能分清四种结局。"""
import asyncio

from part10.a2a.tool_vs_agent import FinanceAgent, Task

TERMINAL = ("completed", "failed", "canceled", "rejected")


class FinanceAgentV2(FinanceAgent):
    def send(self, text: str, task_id: str | None = None) -> Task:
        if "INV-9" in text:  # 假设 INV-9 开头的发票不归这个客户
            task = Task(id=f"task-{next(self._ids)}", state="rejected", question="这张发票不属于该客户,我不处理")
            self.tasks[task.id] = task
            return task
        return super().send(text, task_id)

    def cancel(self, task_id: str) -> Task:
        task = self.tasks[task_id]
        if task.state in TERMINAL:
            raise ValueError(f"{task_id} 已经是终态 {task.state},不能取消")
        for job in list(self._running):
            job.cancel()
        task.state = "canceled"
        return task


async def wait(agent: FinanceAgent, task: Task) -> Task:
    while task.state not in TERMINAL and task.state != "input-required":
        await asyncio.sleep(0.1)
        task = agent.get(task.id)
    return task


async def main() -> None:
    agent = FinanceAgentV2()
    t1 = await wait(agent, agent.send("核对 INV-0042-03 是否重复扣款"))
    print("正常:", t1.state, t1.result)
    t2 = await wait(agent, agent.send("核对 INV-9001-01"))
    print("拒绝:", t2.state, t2.question)
    t3 = agent.send("核对 INV-0042-05")
    await asyncio.sleep(0.1)
    print("取消:", agent.cancel(t3.id).state)
    await asyncio.sleep(0.4)
    print("取消后过了 0.4 秒:", agent.get(t3.id).state)
    try:
        agent.cancel(t1.id)
    except ValueError as e:
        print("取消已完成的:", e)


if __name__ == "__main__":
    asyncio.run(main())
```

<div class="line-notes">

- `class FinanceAgentV2(FinanceAgent):` 继承第 1 步的类,只加新行为,原来的 `send` 逻辑通过 `super().send(...)` 复用。和 JS 的 `class B extends A` 加 `super.send()` 一样。
- `if "INV-9" in text:` rejected 和 failed 不一样:rejected 是对方**决定不做**(不归我管、不合规),failed 是做了但出错了。调用方对两者的处理也不同,rejected 该换个 Agent 或者问人,failed 可以考虑重试。
- `for job in list(self._running):` 取消时把后台还在跑的对账协程都取消掉。这里偷懒取消了全部,真实实现要按任务 id 找到对应的那一个。`list(...)` 先复制一份,因为取消会触发回调从集合里删元素,边遍历边删集合会报错。
- `task.state = "canceled"` 先把状态改成终态。如果不取消后台协程,0.3 秒后 `_reconcile` 会把它又改成 completed,下面那行「过了 0.4 秒」就是在验证这一点。
- `while task.state not in TERMINAL and task.state != "input-required":` 等到终态或者对方要你补信息为止。调用方的等待逻辑必须认识**所有**终态,只认 completed 的话,碰到 rejected 就会永远等下去。

</div>

```bash
uv run python -m part10.a2a.ex614_cancel
```


**练习 2:反过来,你的 Agent 要给别人用。** 第 2 步判断的是「我调别人用什么」。现在反过来:写一个 `interfaces(agent)`,根据谁会来调(同团队、别的团队、外部公司、Claude Desktop 这类聊天应用)和是不是长任务,决定你该开哪几种接口。

<details><summary>参考答案</summary>

```python
# agent-zero-lab/part10/a2a/ex614_expose.py
"""练习 2:反过来,你的 Agent 要给别人用时,该开哪几种接口。"""
from dataclasses import dataclass


@dataclass
class MyAgent:
    name: str
    callers: set[str]  # 谁会来调:"same-team"、"other-team"、"external"、"chat-app"(Claude Desktop 这类)
    long_running: bool = False


def interfaces(a: MyAgent) -> list[str]:
    out: list[str] = []
    if a.callers <= {"same-team"}:
        return ["内部函数 / 子 Agent"]
    if "chat-app" in a.callers or not a.long_running:
        out.append("MCP server:当成一个工具给人家的 Agent 或聊天应用调")
    if a.callers & {"other-team", "external"}:
        out.append("A2A server:当成一个 Agent,带任务状态和多轮")
    return out


if __name__ == "__main__":
    for a in [
        MyAgent("SupportPilot 的分类器", {"same-team"}),
        MyAgent("SupportPilot 整体", {"other-team", "external"}, long_running=True),
        MyAgent("退款金额计算", {"external", "chat-app"}),
        MyAgent("BillSleuth 调查", {"external", "chat-app"}, long_running=True),
    ]:
        print(f"{a.name}:")
        for line in interfaces(a):
            print("   ", line)
```

<div class="line-notes">

- `callers: set[str]` 用集合表示「可能有好几类调用方」。
- `if a.callers <= {"same-team"}:` 集合的 `<=` 是「是不是子集」:调用方只有本团队(或者干脆没有),就不需要任何协议。JS 的 Set 没有这个运算符,得自己写 `[...a].every(x => b.has(x))`。
- `if "chat-app" in a.callers or not a.long_running:` 聊天应用(Claude Desktop、Cursor 这类)今天普遍支持 MCP,不怎么支持 A2A,所以有它就开 MCP;一问一答的短任务,当工具用也最自然。
- `if a.callers & {"other-team", "external"}:` `&` 是集合交集,不为空就说明有跨团队或外部的调用方,他们的 Agent 可能想用 A2A 和你多轮协作。

</div>

```text
    内部函数 / 子 Agent
SupportPilot 整体:
```

**练习 3:MCP 规范发版的节奏。** MCP 规范的版本号是日期。官方仓库 `modelcontextprotocol/modelcontextprotocol` 的 `docs/specification/` 目录下,每个版本一个子目录。用 GitHub 的 contents 接口列出所有版本,算出相邻两版隔了多少天。

<details><summary>参考答案</summary>

```python
# agent-zero-lab/part10/a2a/ex614_mcp_spec.py
"""练习 3:MCP 规范按日期发版。从官方仓库的目录名里列出所有版本,算出相邻两版隔了多少天。"""
from datetime import date

import httpx

URL = "https://api.github.com/repos/modelcontextprotocol/modelcontextprotocol/contents/docs/specification"

with httpx.Client(timeout=20, transport=httpx.HTTPTransport(retries=2)) as client:
    names = [item["name"] for item in client.get(URL).raise_for_status().json()]

versions = sorted(n for n in names if n[:4].isdigit())
print("目录里还有:", [n for n in names if not n[:4].isdigit()])
prev: date | None = None
for v in versions:
    d = date.fromisoformat(v)
    gap = f"隔 {(d - prev).days} 天" if prev else "第一版"
    print(f"{v}  {gap}")
    prev = d
```

<div class="line-notes">

- `URL = "https://api.github.com/repos/modelcontextprotocol/modelcontextprotocol/contents/docs/specification"` contents 接口返回一个目录下的文件和子目录列表,每项有 `name`、`type` 等字段。
- `versions = sorted(n for n in names if n[:4].isdigit())` 前 4 个字符是数字的才是版本目录(年份开头),`draft` 这种排除掉。日期格式 `YYYY-MM-DD` 按字符串排序刚好就是按时间排序,这是这种版本号格式的一个好处。
- `d = date.fromisoformat(v)` 把 `"2025-03-26"` 解析成日期对象。
- `gap = f"隔 {(d - prev).days} 天" if prev else "第一版"` 两个日期相减得到 `timedelta`,`.days` 是天数。JS 里得自己 `(d2 - d1) / 86400000`。

</div>

五个版本,两版之间隔 84 到 245 天,而且间隔在变长:协议越成熟,改动越谨慎。这对你的意义是:用 MCP 写的东西,大概每半年要检查一次规范变了什么(Day 589 讲过 2026 年这一版在授权上的变化)。`draft` 目录是下一版的草稿,想提前知道要变什么就看它。

## 名词解释

| 名词 | 意思 |
| --- | --- |
| A2A(Agent2Agent) | Agent 和 Agent 之间通信的开放协议。对面是不透明的 Agent,任务有状态、可以多轮。2026-03-12 发布 1.0 |
| 不透明(opaque) | 调用方看不到对方 Agent 内部用的模型、工具和提示词,只知道它声明的能力 |
| 任务(task) | A2A 里一次委托的单位,有 id 和状态,多轮消息都挂在它下面 |
| 终态 | 任务结束的状态:completed、failed、canceled、rejected。到了终态不能再发消息 |
| input-required | 对方需要你补充信息的中间状态,不是失败 |
| ACP(Agent Client Protocol) | 编辑器 / 控制台和 Coding Agent 之间的协议,Zed 团队 2025 年 8 月推出,学的是 LSP |
| Agent Communication Protocol | IBM 2025 年 3 月发布的 Agent 间协议,也简称 ACP,2025 年 8 月并入 A2A,已不再单独发展 |
| LSP | Language Server Protocol,编辑器和语言服务之间的协议,VS Code 里的补全和跳转靠它 |
| AAIF | Agentic AI Foundation,Linux 基金会下专管 Agent 开源项目的基金会,托管 MCP、A2A、AGENTS.md、goose、agentgateway |
| 轮询(polling) | 调用方每隔一段时间去查一次任务状态 |
| `a2a-sdk` | A2A 官方 Python SDK 在 PyPI 上的包名。SDK 版本号(1.2.x)和规范版本号(1.0.x)是两回事 |

## 常见误区

**把 A2A 当成 MCP 的替代品。** 它们连的是不同的东西:MCP 连工具和数据,A2A 连别的 Agent。一个 Agent 往往两个都用:用 MCP 查账单库,用 A2A 请财务团队的 Agent 帮忙。

**同一个团队的 Agent 之间也上 A2A。** 第 2 步里 Day 612 的研究员就是反例:它们是 Agent、要跑一会儿,但都是你自己的代码,`asyncio.gather` 一行就并行了。套一层 A2A 只多出网络、序列化和鉴权。

**看到 ACP 就以为是 IBM 那个。** 2025 年上半年的文章里「MCP、A2A、ACP」的 ACP 多半是 IBM 的 Agent Communication Protocol,2025 年 8 月已经并进 A2A。2026 年说 ACP,一般是 Agent Client Protocol。先看日期和全称。

**把 SDK 版本当成规范版本。** `a2a-sdk` 1.2.3 实现的是规范 1.0。问「A2A 现在几版」,答案是规范 1.0.1,不是 1.2.3。

**调用方只认 completed。** 练习 1 里如果等待循环只等 completed,碰到 rejected 就会永远等下去。所有终态都要处理,input-required 也要处理。

**取消只改状态不停动作。** 练习 1 里把取消后台协程的两行注释掉,任务显示 canceled,对方却照样把退款发起了。取消必须真的停下对方的动作。

**相信外部接口「成功了内容就对」。** GitHub 接口偶尔返回 200 加一个空列表,不检查就会在后面的索引上崩。调外部接口时,状态码对了还要检查内容。

## 自测

**1. 从调用方的角度,「对面是 Agent」比「对面是工具」多出了哪三件事?**

<details><summary>答案</summary>

一,对面是不透明的:你看不到它用什么模型、工具、提示词,只知道它声明的能力。二,它有状态、可能跑很久:你拿到的是一个任务 id,要轮询或者等推送才知道结果。三,它会反过来问你:input-required 是正常的中间状态,同一个任务里可以来回多轮。第 1 步的 `FinanceAgent` 三件都演示了,工具 `find_customer` 一件都没有。

</details>

**2. MCP、A2A、ACP 各连哪两样东西?**

<details><summary>答案</summary>

MCP 连 Agent 和工具、数据(账单库、知识库)。A2A 连 Agent 和 Agent(别的团队、别的公司的 Agent)。ACP(Agent Client Protocol)连编辑器或控制台和 Coding Agent,比如 Zed、JetBrains、OpenHands Agent Canvas 去跑 Claude Code 这类 Agent。三者不竞争,一个 Agent 可以同时用。

</details>

**3. 你同事说「我们的分类 Agent 和回复 Agent 都在 SupportPilot 仓库里,我打算让它们之间用 A2A 通信,更规范」。你怎么回应?**

<details><summary>答案</summary>

不建议。同一个代码库、同一个团队的 Agent,直接函数调用或者子 Agent 就行,A2A 解决的是「对面不透明、独立部署、独立发版」的问题,它们都不存在。套一层 A2A 只多出网络开销、序列化、鉴权和一个要维护的服务。等哪天分类 Agent 要开放给别的团队用,再给它加 A2A 接口也不迟。

</details>

**4. 一篇 2025 年 5 月的文章说「ACP 是 IBM 推的 Agent 间协议,和 A2A 竞争」。2026 年的你读到它,要注意什么?**

<details><summary>答案</summary>

那个 ACP 是 IBM 的 Agent Communication Protocol,2025 年 8 月已经并入 A2A,不再单独发展,IBM 的项目页上写着「ACP is now part of A2A」。2026 年说的 ACP 一般指 Agent Client Protocol,是编辑器和 Coding Agent 之间的协议,和 A2A 不是一个层面。读协议类文章先看日期,再看缩写的全称。

</details>

**5. 面试题:A2A 现在是什么状态?你会在什么场景下用它?**

<details><summary>答案</summary>

状态:Google 2025 年 4 月发布,6 月捐给 Linux 基金会,2026 年 3 月 12 日发布 1.0 稳定版(和 0.3 不兼容),5 月发 1.0.1,8 月 17 日加入 Linux 基金会下的 Agentic AI Foundation,和 MCP 同属一个基金会;支持的组织超过 150 家,微软、AWS 已接入平台;官方 Python SDK 是 `a2a-sdk`。治理中立、有稳定版,具备成为标准的条件,但实际用法还在早期,发现机制最不成熟。

场景:跨团队或跨公司、对方 Agent 独立部署和发版、任务可能跑很久或需要多轮交互时用 A2A,比如 SupportPilot 请财务团队的对账 Agent 核对重复扣款。同一个团队内部的 Agent 用函数调用或子 Agent。把自己的 Agent 开放给外部时,同时提供 MCP 和 A2A 两种接口,让调用方按需选。

</details>
