## 今天要解决的问题

今天的新东西是两个:**事实源**(把每个数字只写一次的那份数据)和**确定性渲染**(同样的输入永远渲染出一字不差的输出)。学完你应该能:

1. 解释为什么这 62 篇文章不让大模型写,并且拿得出实测数据:同一个提示词写三遍,政策数字三次不同。
2. 写出 `scripts/kb_facts.py`(事实源)和 `scripts/gen_kb.py`(渲染器),运行后 `data/kb/` 里有 62 个 `.md` 文件,每个都有 frontmatter。
3. 写出 `scripts/check_kb.py`,抓出编号不一致、标题重复、断掉的《交叉引用》、没有对应文章的报错码;并且亲眼看它抓出一处我自己写错的引用。
4. 说清为什么要固定更新日期、为什么要有一条「提交的文章必须和现在渲染出来的一字不差」的测试。

预计用时 3 小时。前置:[Day 222](/blog/agent-zero/day-222-kb-data/) 你造过一份小的 CloudLedger 帮助中心,今天是它的正式版;[Day 37](/blog/agent-zero/day-037-pathlib/) 的路径、[Day 38](/blog/agent-zero/day-038-files-with/) 的读写文件、[Day 23](/blog/agent-zero/day-023-comprehensions/) 的推导式、[Day 73](/blog/agent-zero/day-073-pytest-3/) 的 pytest、[Day 442](/blog/agent-zero/day-442-config/) 的 `Settings`。今天**调模型约 9 次**,都是小实验,总共花了约 ¥0.008,算式在对应的步骤里。

学法:先对照逐行敲一遍(不复制粘贴)并跑通;第二天合上文章,把 `render()` 函数和 `check_kb.py` 里「交叉引用」那一段默写出来;做练习,做不出再展开参考答案,看完关掉重写一遍。

## 先从前端看:帮助中心就是一个静态站

你用过 Docusaurus、VitePress 或者 Astro 的话,这件事不陌生:文档站的每一页是一个带 frontmatter 的 markdown 文件,构建脚本读它们、生成页面。更讲究的团队不会手写每一页里的价格,而是有一份 `pricing.json`,页面里写 `{{price.standard}}`,改价格只改一处。今天做的就是这个模式:

| 前端文档站 | 今天 |
| --- | --- |
| 带 frontmatter 的 `.md` 页面 | `data/kb/KB-refund-002.md` |
| `pricing.json` / i18n 字典 | `scripts/kb_facts.py` 里的事实常量 |
| 构建脚本把数据渲染成页面 | `scripts/gen_kb.py` |
| 链接检查器(找 404) | `scripts/check_kb.py` |

差别只在一点:这个帮助中心不是给人逛的,是给 Agent 检索、给评测当标准答案用的。所以「同一个事实全站一致」比「文章写得好看」重要得多。

## 第一步:为什么不让大模型写

最直觉的做法是:写个循环,让模型一篇一篇地写。我先试了这个,因为想知道它到底差在哪。新建 `scratch/llm_try.py`,让模型把同一篇文章写三遍:

```python
# supportpilot/scratch/llm_try.py
"""试一下:让模型直接写帮助中心文章,每次写得一样吗?"""

import re
import sys

from openai import OpenAI

from supportpilot.config import get_settings

s = get_settings()
client = OpenAI(base_url=s.llm_base_url, api_key=s.llm_api_key.get_secret_value())

PROMPT = "你是 SaaS 产品「云簿 CloudLedger」(在线记账软件)的帮助中心编辑。写一篇 150 字以内的帮助中心文章,标题:年付订阅超过无理由期限后怎么退款。要有具体的数字。只输出正文。"

n = int(sys.argv[1]) if len(sys.argv) > 1 else 3
total_in = total_out = 0
for i in range(n):
    r = client.chat.completions.create(
        model=s.llm_model, messages=[{"role": "user", "content": PROMPT}], extra_body=s.llm_extra_body
    )
    text = r.choices[0].message.content or ""
    assert r.usage
    total_in += r.usage.prompt_tokens
    total_out += r.usage.completion_tokens
    print(f"--- 第 {i + 1} 次 ---")
    print(text)
    print("出现的数字:", re.findall(r"\d+(?:\.\d+)?\s*(?:%|天|个月|元|个工作日)", text))

cost = (total_in * s.price_in_per_m + total_out * s.price_out_per_m) / 1_000_000
print(f"\n输入 {total_in} token,输出 {total_out} token,按高峰价约 ¥{cost:.4f}")
```

<div class="line-notes">

- `import re` 后面用正则从文章里抽数字。
- `import sys` 读命令行参数,决定写几遍。
- `from openai import OpenAI` Day 441 装的 `openai` 包。DeepSeek 兼容 OpenAI 协议,所以用同一个客户端,只换地址和 key。
- `from supportpilot.config import get_settings` [Day 442](/blog/agent-zero/day-442-config/) 的配置。今天第一次用上它:地址、key、模型名、单价全从这里来,脚本里没有一个密钥。
- `client = OpenAI(base_url=s.llm_base_url, api_key=s.llm_api_key.get_secret_value())` `SecretStr` 在这里才调用 `get_secret_value()` 取出原文,只在真正发请求的这一行用一次。
- `PROMPT = "你是 SaaS 产品「云簿 CloudLedger」` 故意只说「年付订阅超过无理由期限后怎么退款」,**不给任何具体数字**。现实里就是这样:写手(或模型)手边没有统一的事实表。
- `n = int(sys.argv[1]) if len(sys.argv) > 1 else 3` `sys.argv` 是命令行参数列表,`sys.argv[1]` 是脚本名后面的第一个。没传就是 3。
- `total_in = total_out = 0` 累计 token 数,最后算钱。
- `for i in range(n):` 循环 n 次,每次一次独立的调用,互不知道对方写了什么。
- `model=s.llm_model, messages=[{"role": "user", "content": PROMPT}], extra_body=s.llm_extra_body` 模型名取自配置(`deepseek-flash`),`extra_body` 是 Day 442 那个字典,关掉思考模式,省时间也省钱。
- `text = r.choices[0].message.content or ""` 取回答的文字。`or ""` 防止内容是 `None`。
- `assert r.usage` 确认响应里带了用量。这一行同时让类型检查器知道下面的 `r.usage` 不是 `None`。
- `total_in += r.usage.prompt_tokens` 累加输入和输出 token。
- `print("出现的数字:", re.findall(r"\d+(?:\.\d+)?\s*(?:%|天|个月|元|个工作日)", text))` 正则找「数字加单位」:`\d+(?:\.\d+)?` 是整数或小数,后面可以有空白,再跟 `%`、天、个月、元、个工作日之一。
- `cost = (total_in * s.price_in_per_m + total_out * s.price_out_per_m) / 1_000_000` 成本 = (输入 token × 输入单价 + 输出 token × 输出单价) ÷ 一百万。单价是 Day 442 里的高峰价,按最贵的算。`1_000_000` 里的下划线只是方便读数的分隔符。

</div>

三篇文章,三种完全不同的退款政策:第一篇说「扣 50 元手续费」,第二篇说「连续 3 个月没用才能退」,第三篇说「按剩余月份分档退 50% 或 30%,手续费 2%」。三篇都说无理由期限是 7 天(我们的政策是 14 天)。模型写得很流畅,每一篇单独看都像那么回事,而且每一篇都是编的。

如果把这三篇都放进知识库,Agent 回答「年付超过无理由期限怎么退」时,取决于检索到哪一篇,会说出三种不同的话,而且三种都不对。评测也没法做:标准答案是哪一篇?

算一下钱,因为很多人以为不用模型是为了省钱。这三篇一共花了 ¥0.0024,每篇约 ¥0.0008。62 篇如果都这么写,大约 62 × 0.0008 ≈ ¥0.05。**钱不是问题。问题是一致性。**

那把事实喂给它呢?这个对照我留到第六步,等事实源写好再做,结果比你想象的复杂一点。先说结论:我的选择是用模板渲染,不用模型写,理由三个。第一,**评测要有标准答案**:事实只写一次,文章和评测集都从同一份事实来,不会打架。第二,**可复现**:别人克隆仓库跑一遍 `gen_kb.py`,拿到的文章一字不差,分数才能对比。第三,**能自动检查**:模板出来的文章结构固定,编号、引用、报错码都能写脚本验。

代价也要老实说:模板写出来的文章很板,不像真实帮助中心那样有长有短、有废话有截图。对我们这个项目可以接受:检索和问答的难点在客户的问法千变万化,不在文章本身。真实项目里你拿到的是公司现成的帮助中心,不用造。

## 第二步:一篇文章长什么样

先不管 62 篇,手工渲染一篇,看最终要产出的是什么。`scratch/mini_gen.py`:

```python
# supportpilot/scratch/mini_gen.py
article = {
    "id": "KB-refund-002",
    "title": "年付 14 天无理由退款",
    "category": "refund",
    "sections": [
        ("条件", "首次购买的年付订阅,从付款日起 14 天内(含第 14 天)申请,全额退款,不需要说明理由。"),
        ("不适用", "续费订单、企业版合同订单不适用 14 天无理由退款。"),
    ],
}

num = article["id"].rsplit("-", 1)[1]
head = (
    f"---\nid: {article['id']}\ntitle: {article['title']}\ncategory: {article['category']}\n"
    f"url_path: /help/{article['category']}/{num}\n---\n\n# {article['title']}\n"
)
body = "".join(f"\n## {h}\n\n{t}\n" for h, t in article["sections"])
print(head + body)
print(repr("KB-error-005".rsplit("-", 1)))
```

<div class="line-notes">

- `article = {` 一篇文章用一个字典描述:编号、标题、分类、小节列表。
- `"id": "KB-refund-002",` 编号格式是 `KB-分类-三位数字`,刻意定死。后面质检时用一个正则就能查有没有编造编号。
- `"sections": [` 小节是 `(小标题, 正文)` 元组的列表,顺序就是文章里的顺序。
- `num = article["id"].rsplit("-", 1)[1]` `rsplit("-", 1)` 从右边切一刀,只切一次。`"KB-refund-002"` 变成 `['KB-refund', '002']`,`[1]` 取最后一段 `'002'`。用 `split("-")` 也能拿到,但从右边切不怕分类名里带连字符。
- `head = (` 文件开头的 frontmatter:两行 `---` 中间是 `key: value`。括号里两个字符串字面量相邻,Python 自动拼成一个。
- `f"url_path: /help/{article['category']}/{num}\n---\n\n# {article['title']}\n"` f-string 里面又用到了字典取值,外层是双引号,里层要用单引号。`url_path` 由分类和编号拼成,将来客户能点的链接就是它。
- `body = "".join(f"\n## {h}\n\n{t}\n" for h, t in article["sections"])` 每个小节变成「二级标题加正文」。`for h, t in ...` 把元组拆成两个变量;`"".join(...)` 把所有小节拼成一个字符串。
- `print(head + body)` 打印整篇。
- `print(repr("KB-error-005".rsplit("-", 1)))` 验证上面说的 `rsplit` 的行为。

</div>

用前端的话说:上半截是 `pricing.json`,下半截是用到它的页面。新建 `scripts/kb_facts.py`,先写上半截:

```python
# supportpilot/scripts/kb_facts.py
"""CloudLedger 帮助中心的"事实源"。评测集的标准答案也从这里来,改这里就要重跑造数 + 评测。"""

# ---------- 事实:每个数字只在这里写一次,文章里用 {名字} 引用 ----------
STD_MONTH, PRO_MONTH = 39, 99  # 标准版、专业版月付价(元)
YEAR_DISCOUNT = 0.8  # 年付八折
STD_YEAR = round(STD_MONTH * 12 * YEAR_DISCOUNT)  # 374
PRO_YEAR = round(PRO_MONTH * 12 * YEAR_DISCOUNT)  # 950
SEAT_PRICE, SEAT_MIN = 59, 5  # 企业版每席每月价、最少席位
ENT_YEAR = SEAT_PRICE * SEAT_MIN * 12  # 3540,最低年费
FIRST_DAYS = 14  # 年付首购无理由退款天数(含第 14 天)
RENEW_DAYS = 7  # 年付续费后可全额退款的天数
FEE_PCT = 10  # 年付超过无理由期限后退款的手续费百分比
REVIEW_LINE = 1000  # 超过这个金额的退款要财务复核(元)

ENTERPRISE = (
    f"企业版按席位计费,每人每月 {SEAT_PRICE} 元,最少 {SEAT_MIN} 席,"
```

<div class="line-notes">

- `# supportpilot/scripts/kb_facts.py` 第一行是文件路径。
- `"""CloudLedger 帮助中心的"事实源"。` 文件最前面的说明写明了它的地位:评测集的标准答案也从这里来,改了它要重新造数、重跑评测。
- `STD_MONTH, PRO_MONTH = 39, 99` 同时给两个变量赋值([Day 22](/blog/agent-zero/day-022-tuples-unpack/) 的元组解包)。标准版、专业版月付价,单位元。
- `YEAR_DISCOUNT = 0.8` 年付八折。
- `STD_YEAR = round(STD_MONTH * 12 * YEAR_DISCOUNT)  # 374` **年付价不手写,算出来**:39 × 12 × 0.8 = 374.4,四舍五入是 374。这样「年付是月付的八折」这条规则和 374 这个数字不会各说各话。
- `PRO_YEAR = round(PRO_MONTH * 12 * YEAR_DISCOUNT)  # 950` 99 × 12 × 0.8 = 950.4,得 950。实测 `round(374.4)` 是 374、`round(950.4)` 是 950。
- `SEAT_PRICE, SEAT_MIN = 59, 5` 企业版每席每月 59 元,最少 5 席。
- `ENT_YEAR = SEAT_PRICE * SEAT_MIN * 12  # 3540,最低年费` 59 × 5 × 12 = 3540,同样是算出来的。
- `FIRST_DAYS = 14` 年付首购无理由退款的天数,含第 14 天。这是整门课里最重要的一个常量,Day 436 的退款规则表、Day 452 的资格函数、Day 476 的评测集都要和它一致。
- `RENEW_DAYS = 7` 年付自动续费后几天内可以全额退。
- `FEE_PCT = 10` 超过无理由期限后退款,扣 10% 手续费。
- `REVIEW_LINE = 1000` 超过 1000 元的退款要财务复核,和 Day 442 的 `refund_review_threshold` 是同一个数。
- `ENTERPRISE = (` 企业版的说明有两篇文章要用(套餐对比、企业版与席位),抽成一个字符串,保证两处一字不差。
- `f"企业版按席位计费,每人每月 {SEAT_PRICE} 元,最少 {SEAT_MIN} 席,"` f-string,花括号里放变量名。拼出来是「每人每月 59 元,最少 5 席」。
- `f"只能年付(起步 {ENT_YEAR:,} 元/年)` 花括号里 `:,` 是格式说明:加千分位逗号。`3540` 变成 `3,540`。

<div class="line-notes">

- `ARTICLES: list[dict] = [` 所有文章放进一个列表。`list[dict]` 是类型标注([Day 46](/blog/agent-zero/day-046-type-hints-2/))。
- `{"id": "KB-plans-001",` 套餐对比。编号里的 `plans` 是分类,`001` 是序号。
- `("价格", f"免费版 0 元。标准版 {STD_MONTH} 元/月,年付 {STD_YEAR} 元。` 正文前面加了 `f`,花括号里的名字会被换成上面定义的值。这一节渲染出来是「标准版 39 元/月,年付 374 元。专业版 99 元/月,年付 950 元」。行尾的 `+ ENTERPRISE` 是字符串拼接:这一节的完整内容是前半段加上 `ENTERPRISE` 常量。
- `("功能差异", "账套数量:免费版 1 个、标准版 3 个、专业版 10 个。` 这一节正文很长,分好几行写:括号里相邻的字符串字面量自动拼成一个。这些数字(账套数、导入行数、API 限流)只出现在一两篇里,我没有做成常量。哪些数字该提成事实,哪些就地写,标准是「评测会不会用它出题」。
- `("退款规则不同", f"月付不支持退款,只能关闭自动续费,当期到期后停止。年付首次购买 {FIRST_DAYS} 天内可无理由全额退款,详见《退款政策总览》。")` 这一句有两处值得看:`{FIRST_DAYS}` 引用事实;`《退款政策总览》` 是在指向另一篇文章的标题,第五步的检查脚本会专门验证这类引用能不能找到对应的文章。
- `补差价约为 ({PRO_MONTH} - {STD_MONTH}) × 15 / 30 = {(PRO_MONTH - STD_MONTH) * 15 / 30:g} 元。` 升级补差价的例子也是算出来的:(99 - 39) × 15 / 30 = 30.0,`:g` 格式说明把 `30.0` 显示成 `30`。
- `("计费", ENTERPRISE),` 企业版那篇直接放 `ENTERPRISE`,和套餐对比里那一句一字不差。
- `("试用", "新注册账户可免费试用专业版 14 天,不需要绑定支付方式。")` 注意这里的 14 是**试用天数**,和退款的 `FIRST_DAYS` 恰好都是 14,但不是同一个事实,所以我没有用 `FIRST_DAYS`。两个事实今天值一样,哪天政策变了不一定一起变。

## 第四步:渲染器 gen_kb.py

接着写把事实变成文件的脚本。新建 `scripts/gen_kb.py`:

```python
# supportpilot/scripts/gen_kb.py
"""把 kb_facts 里的事实渲染成帮助中心 markdown,写到 data/kb/。确定性输出,可重复运行。"""

from pathlib import Path

from kb_facts import ARTICLES, ERRORS

OUT = Path(__file__).resolve().parent.parent / "data" / "kb"
UPDATED = "2026-09-15"

Doc = tuple[str, str, str, list[tuple[str, str]]]  # (编号, 标题, 分类, [(小标题, 正文)])


def render(doc_id: str, title: str, category: str, sections: list[tuple[str, str]]) -> str:
    num = doc_id.rsplit("-", 1)[1]
    head = (
        f"---\nid: {doc_id}\ntitle: {title}\ncategory: {category}\n"
        f"updated_at: {UPDATED}\nurl_path: /help/{category}/{num}\n---\n\n# {title}\n"
    )
    body = "".join(f"\n## {h}\n\n{t}\n" for h, t in sections)
    return head + body


def error_doc(i: int, code: str, name: str, module: str, cause: str, steps: list[str]) -> Doc:
    steps_md = "\n".join(f"{n}. {s}" for n, s in enumerate(steps, start=1))
    return (
        f"KB-error-{i:03d}",
        f"{code} {name}",
        "error",
        [
            ("报错含义", f"界面提示 {code}「{name}」。"),
            ("原因", cause),
            ("处理步骤", steps_md),
            ("仍未解决", f"请提交工单并附上报错截图、报错码 {code} 和发生时间。所属模块:{module}。"),
        ],
    )


def build_docs() -> list[Doc]:
    docs: list[Doc] = [(a["id"], a["title"], a["category"], a["sections"]) for a in ARTICLES]
    for i, (code, name, module, cause, steps) in enumerate(ERRORS, start=1):
        docs.append(error_doc(i, code, name, module, cause, steps))
    return docs


def main() -> None:
    OUT.mkdir(parents=True, exist_ok=True)
    for old in OUT.glob("*.md"):
        old.unlink()
    docs = build_docs()
    for doc_id, title, category, sections in docs:
        (OUT / f"{doc_id}.md").write_text(render(doc_id, title, category, sections), encoding="utf-8")
    print(f"wrote {len(docs)} articles to {OUT}")


if __name__ == "__main__":
    main()
```

<div class="line-notes">

- `from pathlib import Path` 路径对象。
- `from kb_facts import ARTICLES, ERRORS` 没写包名,因为 `scripts/` 不是包。所以要在 `scripts/` 里运行,或者让 `scripts/` 进入 Python 的搜索路径(第七步)。
- `OUT = Path(__file__).resolve().parent.parent / "data" / "kb"` 输出到仓库根目录下的 `data/kb/`。`__file__` 是脚本自己的位置,往上两级是仓库根目录。
- `UPDATED = "2026-09-15"` 更新日期**写死**,不用 `date.today()`。每次渲染出来的文件一字不差,`git diff` 才不会因为日期变了而出现 62 个假改动。
- `Doc = tuple[str, str, str, list[tuple[str, str]]]` 给一个长类型起个名字:(编号, 标题, 分类, 小节列表)。后面函数签名里写 `Doc` 就行。
- `def render(doc_id: str, title: str, category: str, sections: list[tuple[str, str]]) -> str:` 一篇文章变成 markdown 字符串。纯函数:只做字符串拼接,不读不写文件,所以好测。
- `num = doc_id.rsplit("-", 1)[1]` 和第二步一样,取出编号最后的 `002`。
- `head = (` frontmatter,比第二步多了 `updated_at`。
- `f"updated_at: {UPDATED}\nurl_path: /help/{category}/{num}\n---\n\n# {title}\n"` `url_path` 就是将来 Day 451 把 `[KB-refund-002]` 换成客户能点的链接时用的路径。
- `body = "".join(f"\n## {h}\n\n{t}\n" for h, t in sections)` 每个小节变成二级标题加正文。
- `def error_doc(i: int, code: str, name: str, module: str, cause: str, steps: list[str]) -> Doc:` 报错码文章由模板生成。
- `steps_md = "\n".join(f"{n}. {s}" for n, s in enumerate(steps, start=1))` `enumerate(..., start=1)` 让序号从 1 开始。以 E3001 为例,得到三行:`1. 进入「银行账户」点击「重新授权」` / `2. 授权成功后点「立即同步」` / `3. 仍失败的,确认网银没有修改密码或注销`。
- `f"KB-error-{i:03d}",` `{i:03d}` 补零到三位:5 变成 `005`。
- `f"{code} {name}",` 标题是「报错码加空格加名称」,比如 `E3001 银行流水同步失败`。第五步的检查就靠「标题以报错码加空格开头」来认。
- `"error",` 报错码文章的分类统一是 `error`,原来的模块名写进正文最后一节。
- `("报错含义", f"界面提示 {code}「{name}」。"),` 四个固定小节:含义、原因、处理步骤、仍未解决。
- `("仍未解决", f"请提交工单并附上报错截图、报错码 {code} 和发生时间。所属模块:{module}。"),` 每篇报错码文章的最后一节都是同一个模板。
- `def build_docs() -> list[Doc]:` 把所有文章整理成统一的 `Doc` 格式,**不写文件**。单独成函数,是为了让检查脚本和测试能直接调它。
- `docs: list[Doc] = [(a["id"], a["title"], a["category"], a["sections"]) for a in ARTICLES]` 50 篇手写文章,先整理成 4 元组。
- `for i, (code, name, module, cause, steps) in enumerate(ERRORS, start=1):` 同时拿序号和 5 元组,`(code, name, ...)` 直接把元组拆开。以第 5 个为例:`i=5`、`code='E3001'`。
- `docs.append(error_doc(i, code, name, module, cause, steps))` 12 篇报错码文章接在后面。
- `def main() -> None:` 真正写文件的入口。
- `OUT.mkdir(parents=True, exist_ok=True)` 目录不存在就连上级一起建,已存在也不报错。
- `for old in OUT.glob("*.md"):` 先删光旧的 `.md` 再写。不删的话,改过编号的文章旧文件会一直留着,Day 449 导入时就多出一篇过时的文章。`.gitkeep` 不是 `.md`,不会被删。
- `(OUT / f"{doc_id}.md").write_text(render(doc_id, title, category, sections), encoding="utf-8")` 文件名就是编号。`encoding="utf-8"` 每次显式写,不靠系统默认。
- `print(f"wrote {len(docs)} articles to {OUT}")` 打印写了多少篇。
- `if __name__ == "__main__":` 直接运行才执行 `main()`,被 import 时不会写文件。

</div>

## 第五步:检查脚本 check_kb.py,以及它抓出的一处错

62 篇文章人眼看不过来。写个脚本替我们看。它要查五类问题:文章数够不够、编号对不对、frontmatter 和文件名一致不一致、标题有没有重复、**文章里提到的别的文章(《……》)是不是真有**、提到的报错码有没有对应的报错码文章。新建 `scripts/check_kb.py`:

```python
# supportpilot/scripts/check_kb.py
"""检查 data/kb/ 里的帮助中心文章:编号、frontmatter、交叉引用、报错码。有问题就退出码 1。"""

import re
import sys
from pathlib import Path

KB = Path(__file__).resolve().parent.parent / "data" / "kb"
ID_RE = re.compile(r"^KB-(plans|billing|invoice|refund|account|technical|api|error)-(\d{3})$")
MIN_ARTICLES = 60


def read_meta(text: str) -> dict[str, str]:
    """读文件开头两行 --- 之间的 key: value。"""
    head = text.split("---", 2)[1]
    return dict(line.split(": ", 1) for line in head.strip().splitlines())


def check(kb_dir: Path = KB) -> list[str]:
    problems: list[str] = []
    files = sorted(kb_dir.glob("KB-*.md"))
    if len(files) < MIN_ARTICLES:
        problems.append(f"文章只有 {len(files)} 篇,要求至少 {MIN_ARTICLES} 篇")

    titles: dict[str, str] = {}  # 标题 -> 编号
    urls: set[str] = set()
    for f in files:
        text = f.read_text(encoding="utf-8")
        meta = read_meta(text)
        doc_id = meta.get("id", "")
        m = ID_RE.match(doc_id)
        if doc_id != f.stem:
            problems.append(f"{f.name}:frontmatter 里的 id 是 {doc_id!r},和文件名不一致")
        if not m:
            problems.append(f"{f.name}:编号格式不对 {doc_id!r}")
        elif m.group(1) != meta.get("category"):
            problems.append(f"{f.name}:编号里的分类 {m.group(1)} 和 category {meta.get('category')} 不一致")
        if meta.get("url_path") in urls:
            problems.append(f"{f.name}:url_path {meta.get('url_path')} 重复")
        urls.add(meta.get("url_path", ""))
        if meta["title"] in titles:
            problems.append(f"{f.name}:标题和 {titles[meta['title']]} 重复")
        titles[meta["title"]] = doc_id
        if "\n## " not in text:
            problems.append(f"{f.name}:没有任何小节(## 标题),后面切块没东西可切")

    all_text = {f.stem: f.read_text(encoding="utf-8") for f in files}
    for doc_id, text in all_text.items():
        for ref in re.findall(r"《([^》]+)》", text):
            if ref not in titles:
                problems.append(f"{doc_id}:引用了《{ref}》,但没有这个标题的文章")
        if doc_id.startswith("KB-error-"):
            continue
        for code in sorted(set(re.findall(r"\bE\d{4}\b", text))):
            if not any(t.startswith(code + " ") for t in titles):
                problems.append(f"{doc_id}:提到报错码 {code},但没有对应的报错码文章")
    return problems


if __name__ == "__main__":
    found = check()
    print(f"检查 {len(list(KB.glob('KB-*.md')))} 篇文章:", "通过" if not found else f"{len(found)} 个问题")
    for p in found:
        print("  -", p)
    sys.exit(1 if found else 0)
```

<div class="line-notes">

- `import re` 正则。
- `import sys` 最后用 `sys.exit` 返回退出码。
- `from pathlib import Path` 路径。
- `KB = Path(__file__).resolve().parent.parent / "data" / "kb"` 默认检查仓库里的 `data/kb/`。
- `ID_RE = re.compile(r"^KB-(plans|billing|invoice|refund|account|technical|api|error)-(\d{3})$")` 编号格式的正则:`KB-` 开头,八个合法分类之一,再 `-` 加恰好三位数字。`re.compile` 先编译,后面反复用。括号是捕获组,`m.group(1)` 取到分类。
- `MIN_ARTICLES = 60` PRD 和大纲都说「60 篇以上」,低于它就报问题。
- `def read_meta(text: str) -> dict[str, str]:` 读 frontmatter。
- `head = text.split("---", 2)[1]` 按 `---` 最多切两刀:前面是空串,中间是 frontmatter,后面是正文。取下标 1 的中间那段。
- `return dict(line.split(": ", 1) for line in head.strip().splitlines())` 每行按第一个 `: ` 切成 (key, value),交给 `dict()` 变成字典。
- `def check(kb_dir: Path = KB) -> list[str]:` 检查函数。参数可以换目录,测试时用临时目录。返回问题列表,空列表代表通过。
- `files = sorted(kb_dir.glob("KB-*.md"))` 取所有 `KB-` 开头的 `.md` 文件,排序让输出稳定。
- `if len(files) < MIN_ARTICLES:` 第一类:数量。
- `titles: dict[str, str] = {}  # 标题 -> 编号` 记下每个标题属于哪篇,用来查重和查引用。
- `urls: set[str] = set()` 记下见过的 `url_path`。
- `for f in files:` 逐个文件检查。
- `doc_id = meta.get("id", "")` `.get` 取不到时给空串,不抛异常。
- `m = ID_RE.match(doc_id)` 编号对不对格式。
- `if doc_id != f.stem:` 第二类:frontmatter 里的 `id` 必须和文件名一致。`f.stem` 是去掉后缀的文件名。
- `if not m:` 编号格式不对。
- `elif m.group(1) != meta.get("category"):` 编号里的分类和 `category` 字段必须一致。
- `if meta.get("url_path") in urls:` `url_path` 不能重复。
- `urls.add(meta.get("url_path", ""))` 记下来。
- `if meta["title"] in titles:` 第三类:标题不能重复。
- `titles[meta["title"]] = doc_id` 记下标题。
- `if "\n## " not in text:` 第四类:至少有一个二级小节,否则后面没东西可切块。
- `all_text = {f.stem: f.read_text(encoding="utf-8") for f in files}` 字典推导式:文件名到全文。
- `for ref in re.findall(r"《([^》]+)》", text):` 第五类:找出所有《……》。正则 `[^》]+` 是「不是 `》` 的任意字符」,括号只取里面的标题。
- `if ref not in titles:` 引用的标题必须**一字不差**地存在于某篇文章的标题里。
- `if doc_id.startswith("KB-error-"):` 报错码文章自己不用查「有没有报错码文章」。
- `for code in sorted(set(re.findall(r"\bE\d{4}\b", text))):` 找出文章里出现的所有报错码(`E` 加四位数字,`\b` 是词边界),去重排序。
- `if not any(t.startswith(code + " ") for t in titles):` 对应的报错码文章,标题必须以「报错码加空格」开头。
- `return problems` 返回问题列表。
- `if __name__ == "__main__":` 命令行入口。
- `print(f"检查 {len(list(KB.glob('KB-*.md')))} 篇文章:"` 先打印检查了几篇和结果。
- `sys.exit(1 if found else 0)` 有问题退出码是 1,CI 或 pre-commit 可以据此判断失败。

脚本抓出一处我自己写错的引用。`KB-billing-003`(扣款失败怎么办)里写了「常见失败原因见《E4001 支付失败》」,但对应的报错码文章标题是 `E4001 支付失败,卡被拒绝`,少了「,卡被拒绝」。书名号里的内容要和标题**一字不差**,这一处没有。人眼看这句话,「E4001 支付失败」读起来毫无问题,我自己写的时候也觉得没问题。

## 第六步:把事实喂给模型,再写一遍

第一步我说过,把事实给模型会怎样,留到事实源写好之后。现在写好了,补这个对照。`scratch/llm_try2.py`:

```python
# supportpilot/scratch/llm_try2.py
"""给模型一份事实再写,三次的数字一样吗?"""

import re

from openai import OpenAI

from kb_facts import FEE_PCT, FIRST_DAYS, PRO_YEAR
from supportpilot.config import get_settings

s = get_settings()
client = OpenAI(base_url=s.llm_base_url, api_key=s.llm_api_key.get_secret_value())

FACTS = (
    f"事实:年付订阅首次购买 {FIRST_DAYS} 天内可无理由全额退款;超过 {FIRST_DAYS} 天,"
    f"按剩余完整月份比例退款并扣除 {FEE_PCT}% 手续费,退款金额 = 年付金额 × 剩余完整月数 / 12 × {100 - FEE_PCT}%。"
    f"例子:专业版年付 {PRO_YEAR} 元,剩余完整月份 7 个。"
)
PROMPT = f"你是 SaaS 产品「云簿 CloudLedger」的帮助中心编辑。只根据下面的事实,写一篇 150 字以内的帮助中心文章,标题:年付订阅超过无理由期限后怎么退款。只输出正文。\n{FACTS}"

total_in = total_out = 0
for i in range(3):
    r = client.chat.completions.create(
        model=s.llm_model, messages=[{"role": "user", "content": PROMPT}], extra_body=s.llm_extra_body
    )
    text = r.choices[0].message.content or ""
    assert r.usage
    total_in += r.usage.prompt_tokens
    total_out += r.usage.completion_tokens
    print(f"--- 第 {i + 1} 次 ---")
    print(text)
    print("出现的数字:", re.findall(r"\d+(?:\.\d+)?", text))
cost = (total_in * s.price_in_per_m + total_out * s.price_out_per_m) / 1_000_000
print(f"\n输入 {total_in} token,输出 {total_out} token,按高峰价约 ¥{cost:.4f}")
```

结果比第一步好得多,但不是没有问题。给了事实之后,三次的数字全部一致:14、10、90、950、7 都是我们给的,没有一个编出来的。可是:第一,三篇长度不一样,第二篇多写了一句例子,**第二篇和第三篇的结构不同**。第二,没有一篇把 `498.75` 算出来。第二篇只是把算式列了出来(`950 × 7 / 12 × 90%`),没有写结果;语言模型做多步乘除并不可靠,这也是整个 Agent 项目里「退款金额要用代码算」的原因。

所以结论要写准确:**给了事实,模型能守住数字,不再乱编,但每次的篇幅和结构还是不同,而且不能指望它算对例子。** 对「造 62 篇作为评测标准答案来源」这个用途,模板更合适。模型的用武之地在别处:改写口吻、扩写客户问法(Day 476 会用),这些都要配一个「数字守卫」检查它有没有动数字,练习 4 就做这个。

花费算式:第一步 3 次,输入 165、输出 265 token,(165 × 2 + 265 × 8) ÷ 1,000,000 = ¥0.0024;这一步 3 次,输入 384、输出 237 token,(384 × 2 + 237 × 8) ÷ 1,000,000 = ¥0.0027。两处都按高峰价,实际可能更便宜(空闲时段是一半)。

<div class="line-notes">

- `[tool.ruff.format]` ruff 排版工具的配置段。
- `exclude = ["scripts/kb_facts.py"]  # 数据文件,保留手写的排版` 这个文件是数据,每篇文章手工排成固定的几行;让 `ruff format` 去重排它,会把每个字典拆成十几行,反而难读,也让 diff 失真。
- `[tool.ruff.lint.per-file-ignores]` 按文件忽略某些检查规则。
- `"scripts/kb_facts.py" = ["E501"]` `E501` 是「行太长」(上限在 Day 441 设成了 120)。ruff 算行宽时,一个汉字占两格,所以一句中文正文很容易超。我实测不加这一行,`ruff check` 对这个文件报了 20 处 `E501`。数据文件里的长句子不该为了行宽被拆开。
- `pythonpath = ["scripts"]` pytest 运行时把 `scripts/` 加进 Python 搜索路径,测试里就能 `import gen_kb`。
- `extraPaths = ["scripts"]` 同样的意思,告诉 basedpyright。

```python
import gen_kb
import kb_facts
```

### 练习 3:故意弄坏文章,看检查脚本各说什么

### 练习 4:让模型改写文章,用「数字守卫」盯着它

**题目:** 让模型把 `KB-refund-003` 改写得更口语,要求不改任何数字。写一个「数字守卫」函数,比较改写前后文章里出现的数字(连出现次数一起比),报告少了或多了哪些。跑 3 次,看守卫有没有抓到问题。

<details><summary>参考答案</summary>

```python
# supportpilot/scratch/ex4_rewrite.py
"""让模型把一篇文章改写得更口语,再用「数字守卫」检查它有没有动数字。"""

import re
import sys
from collections import Counter

from openai import OpenAI

from supportpilot.config import ROOT, get_settings

s = get_settings()
client = OpenAI(base_url=s.llm_base_url, api_key=s.llm_api_key.get_secret_value())


def numbers(text: str) -> Counter[str]:
    """文章里出现的所有数字(含小数),连出现次数一起数。"""
    return Counter(re.findall(r"\d+(?:\.\d+)?", text.replace(",", "")))


def guard(original: str, rewritten: str) -> list[str]:
    a, b = numbers(original), numbers(rewritten)
    return [f"少了 {k}" for k in a - b] + [f"多了 {k}" for k in b - a]


doc_id = sys.argv[1] if len(sys.argv) > 1 else "KB-refund-003"
original = (ROOT / "data" / "kb" / f"{doc_id}.md").read_text(encoding="utf-8").split("---", 2)[2]
prompt = f"把下面这篇帮助中心文章改写得更口语、更亲切,不要增删任何信息,所有数字必须原样保留。只输出改写后的正文。\n{original}"

total_in = total_out = 0
for i in range(3):
    r = client.chat.completions.create(
        model=s.llm_model, messages=[{"role": "user", "content": prompt}], extra_body=s.llm_extra_body
    )
    text = r.choices[0].message.content or ""
    assert r.usage
    total_in += r.usage.prompt_tokens
    total_out += r.usage.completion_tokens
    print(f"--- 第 {i + 1} 次:{guard(original, text) or '数字全部保留'} ---")
    print(text)
cost = (total_in * s.price_in_per_m + total_out * s.price_out_per_m) / 1_000_000
print(f"\n输入 {total_in} token,输出 {total_out} token,按高峰价约 ¥{cost:.4f}")
```

<div class="line-notes">

- `import re` 抽数字用。
- `import sys` 读命令行参数,可以指定别的文章编号。
- `from collections import Counter` `Counter` 是「计数字典」:数一个序列里每个元素出现几次。
- `from supportpilot.config import ROOT, get_settings` 除了配置,还导入了 Day 442 里算出来的仓库根目录 `ROOT`,拿它拼文章路径,从哪个目录运行都行。
- `def numbers(text: str) -> Counter[str]:` 返回「数字 → 出现次数」。
- `return Counter(re.findall(r"\d+(?:\.\d+)?", text.replace(",", "")))` 先把千分位逗号去掉(`2,000` 变 `2000`,免得被拆成 2 和 000),再找所有整数或小数,交给 `Counter` 数。
- `def guard(original: str, rewritten: str) -> list[str]:` 守卫函数:比较两个文本。
- `a, b = numbers(original), numbers(rewritten)` 两边各数一遍。
- `return [f"少了 {k}" for k in a - b] + [f"多了 {k}" for k in b - a]` `Counter` 支持减法:`a - b` 是「原文里有、改写里没有(或更少)的」,`b - a` 反过来。两个都空,就是数字完全一致。
- `doc_id = sys.argv[1] if len(sys.argv) > 1 else "KB-refund-003"` 默认改写 `KB-refund-003`。
- `original = (ROOT / "data" / "kb" / f"{doc_id}.md").read_text(encoding="utf-8").split("---", 2)[2]` 读文章,按 `---` 切两刀,取 frontmatter 后面的正文。
- `prompt = f"把下面这篇帮助中心文章改写得更口语、更亲切,不要增删任何信息,所有数字必须原样保留。只输出改写后的正文。\n{original}"` 提示词里明确要求保留数字。
- `print(f"--- 第 {i + 1} 次:{guard(original, text) or '数字全部保留'} ---")` `guard(...)` 返回空列表时为假,`or` 后面的话就显示出来。

## 名词解释

| 名词 | 意思 |
| --- | --- |
| 事实源(single source of truth) | 一份数据,每个事实只在这里写一次;文章、评测、代码都从它读,不各抄一遍。 |
| 合成数据 | 不是真实业务里收集来的,而是为了开发和评测人工造出来的数据。今天造的帮助中心就是。 |
| frontmatter | markdown 文件开头被两行 `---` 夹住的元数据(`key: value`),比如 `id`、`title`。前端文档站都在用。 |
| 确定性输出 | 同样的输入永远得到一字不差的输出。靠写死日期、固定顺序、不用随机数和系统时钟做到。 |
| 渲染(render) | 把结构化数据(字典、列表)变成最终文本。今天是变成 markdown 文章。 |
| f-string | 字符串前面加 `f`,花括号里可以放变量或表达式,还能加格式说明,比如 `{x:,}` 加千分位、`{x:.2f}` 保留两位小数。 |
| 格式说明 | f-string 花括号里冒号后面的部分。`:,` 千分位,`:.2f` 两位小数,`:g` 去掉多余的零,`:03d` 补零到三位。 |
| 交叉引用 | 文章里提到另一篇文章的标题(《……》)。标题改了、写错了,引用就断了。 |
| 编号漂移 | 编号是用位置算出来的,中间插入一项后,后面所有项的编号都变了,已经发出去的引用悄悄指向错误的对象。 |
| 数字守卫 | 一个机械的小检查:比较改写前后文本里的数字,多了少了就报警,不再让模型自己检查自己。 |
| `tmp_path` | pytest 自带的 fixture,给每个测试一个独立的临时目录,测试完自动清理。 |
| `Counter` | `collections` 里的计数字典,数一个序列里每个元素出现几次,两个 `Counter` 可以相减。 |

## 常见误区

**以为不用模型是为了省钱。** 我实测过:62 篇都让模型写,约 ¥0.05。钱不是原因。原因是同一个提示词写三遍,政策数字三遍不同(手续费 50 元、没有手续费、2%),放进知识库就是三个互相矛盾的「事实」。

**以为把事实喂给模型就万事大吉。** 喂了之后数字确实稳了(三次都是 14、10、90、950、7),但篇幅和结构仍然每次不同,而且它没有算出例子的结果 `498.75`。需要精确数字的地方,用代码算。

**把偶然相同的数字提成同一个常量。** 试用 14 天、退款 14 天、扣款失败第 14 天都是 14,但是三个事实。合并成一个 `DAYS = 14`,哪天只改一个,另外两处就悄悄错了。要问的是「这两个数一定会一起变吗」,不是「它们现在一样吗」。

**只改正文,不改标题和小标题。** 我自己第一版就是这样:正文用了 `{FIRST_DAYS}`,小标题却是字面量 `"年付超过 14 天"`,练习里一改常量就出现「标题 14 天、正文 30 天」。引用事实的地方,标题也要引用。

**用位置当编号。** `enumerate(ERRORS, start=1)` 生成 `KB-error-001`、`002`……看起来省事,但一旦中间插入,后面全部漂移。编号一旦发出就不能变,新条目追加在末尾;或者在数据里显式写编号。

**生成文件里混进日期或随机数。** `UPDATED` 如果写成 `date.today()`,每天重新生成都会改 62 个文件的 frontmatter,`git diff` 满屏假改动,真改动被淹没,「提交的文章必须和渲染一致」的测试也没法写。

**书名号里的标题写成大概。** 「《E4001 支付失败》」读起来毫无问题,但真实标题是「E4001 支付失败,卡被拒绝」,引用就断了。人眼看不出来,脚本一下就抓出。

**把 `scripts/` 当成包。** 它里面没有 `__init__.py`,`import gen_kb` 找不到,是 `pythonpath` 才让它能 import。如果你嫌别扭,把它们放进 `src/supportpilot/` 也行,但那就变成了应用代码的一部分,这里选择让它们保持「工具脚本」的身份。

**让 ruff 去排版数据文件。** `kb_facts.py` 里每个文章手排成几行,让 `ruff format` 重排会把每个字典拆成十几行;中文句子一行就超 120 格(汉字占两格),`E501` 报 20 处。数据文件在 `pyproject.toml` 里单独放宽。

1. 为什么这 62 篇文章用模板生成,而不让大模型来写?

<details><summary>答案</summary>

不是为了省钱,62 篇让模型写也就 ¥0.05。原因有三:评测要有标准答案,事实只写一次,文章和评测集才不会打架;可复现,别人跑一遍得到一字不差的文章,分数才能比;能自动检查,模板出的结构固定,编号、引用、报错码都能写脚本验。我实测过:同一个提示词写三遍,三篇的退款政策各不相同(手续费 50 元、没有手续费、2%),全是编的;给了事实后数字稳了,但篇幅结构仍然不同,也没算出 498.75。

</details>

2. `kb_facts.py` 里年付价 374 和 950 为什么是算出来的,不是手敲的?

<details><summary>答案</summary>

因为「年付是月付的八折」这条规则和 374、950 两个数字是同一个事实的两个表现。手敲的话,哪天改了折扣或月付价,忘了改年付价,文章就自相矛盾。算出来的:`round(39 * 12 * 0.8)` = 374、`round(99 * 12 * 0.8)` = 950,改一处全站跟着变。测试 `test_derived_prices` 还会拿它们和对外说的数字对账。

</details>

3. 什么时候该把一个数字提成常量,什么时候就地写?试用 14 天和退款 14 天为什么没合并?

<details><summary>答案</summary>

标准是两个:这个数字会不会在多处出现、评测会不会用它出题;以及「它们一定会一起变吗」。试用 14 天和退款 14 天碰巧同值,但是两个事实,政策调整时不一定一起变,合并了反而会让改一个、悄悄改了另一个。所以退款相关的(`FIRST_DAYS`、`RENEW_DAYS`、`FEE_PCT`、`REVIEW_LINE`)和价格提成常量,试用天数、导入行数这类就地写。

</details>

4. `check_kb.py` 抓出了什么问题?怎么修?

<details><summary>答案</summary>

抓出 `KB-billing-003` 里的「《E4001 支付失败》」断链:书名号里要和某篇文章的标题一字不差,而真实标题是「E4001 支付失败,卡被拒绝」。修法是把引用改成完整标题。人眼读起来没问题,脚本一下就查出来。这类断链会让 Agent 顺着引用去找一个不存在的标题。

</details>

5. 报错码文章的编号是用位置算的(`enumerate`),为什么这有风险?

<details><summary>答案</summary>

中间插入一项,后面所有项的位置都往后挪一位,编号跟着变。练习 2 实测:把 `E4003` 插在 `E5001` 前面,`KB-error-011` 从指 `E5001` 变成指 `E4003`,`E5001` 变成 012。编号是被引用的(回答里的 `[KB-error-011]`、评测集里写死的期望编号、日志),发出去的编号换了指向,旧引用悄悄变错。所以编号一旦发出就不能变,新条目追加在末尾,或在数据里显式写编号。

</details>

6. **面试题**:「你的 RAG 项目里,知识库的数据是怎么来的?怎么保证评测的标准答案和知识库一致?」

<details><summary>答案</summary>

这个项目的帮助中心是我造的合成数据(真实项目里是公司现成的)。我没有让大模型直接写文章,因为实测同一个提示词写三遍,政策数字三次不同,放进知识库会得到互相矛盾的「事实」。我做了一份事实源:价格、退款天数、手续费这些数字只写一次,年付价这类还是算出来的,文章模板用 f-string 引用它们,评测集里的标准答案也从同一份事实来,所以不会打架。生成是确定性的:日期写死,输出一字不差,我加了一条测试保证提交进仓库的文章和现在渲染出来的完全一致,改了事实忘了重新生成会立刻红。另外写了检查脚本验编号、frontmatter、标题重复、交叉引用和报错码,它当场抓出我自己写错的一处断链。如果要让模型参与改写,我会加一个机械的数字守卫,比较改写前后的数字,而不是让模型自己检查自己。

</details>
