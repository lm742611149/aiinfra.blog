第一题和第二题,向量检索勉强对了:正确答案排第一,但后面跟着的 E1042、E2017、E3001 是别的错误码,分数只差 0.1 左右,在模型眼里它们都是"一篇讲错误码的文章"。第三题就翻车了:前三名全是"导入导出"主题的块,**真正讲 E2017 的两块一个都没有进前三**。它们实际排在第 7 和第 8 名(明天的 RRF 会把完整排名摊开)。

原因不难想。embedding 模型把一句话压成一个向量,表达的是"这句话大体在说什么"。`E2017` 对它来说只是几个陌生的字符,它没法像人一样注意到"这个编号必须一字不差地匹配"。"导入"这个词意思很明确,所以向量被拉去了和导入相关的块。最后一题反过来:问题里没有一个词和文章重合,向量检索却排对了。这正是它的长处。

所以我们需要一路"只看字面"的检索,和向量互补。它不用理解任何意思,只要问题里的词在哪块里出现得多、出现得稀罕,就给哪块高分。这类算法有个名字,叫**关键词检索**,最经典的实现是 BM25。

## BM25 是什么:数词的三条规矩

BM25 是搜索引擎用了几十年的打分算法(Elasticsearch 默认的相关性算法就是它)。名字里的 BM 是 "Best Matching"(最佳匹配),25 是试到第 25 个版本的函数。你要记住的就是三条规矩,每一条对应现实里一个很朴素的直觉。

**第一条:词出现得越多,分越高,但有上限。** 「退款」在一块里出现 1 次和出现 2 次,差别很大;出现 20 次和 21 次,几乎没差别。这叫**词频饱和**。

**第二条:词在越少的块里出现,越重要。** 「的」「是」每块都有,没有区分度;`E2017` 只在两块里出现,一旦匹配上就是强信号。这叫**逆文档频率**(IDF,Inverse Document Frequency)。

**第三条:块越长,分数越要打折。** 一块里有 200 个词,偶然提到一次「退款」,不应该比一块 20 个词、专门讲退款的得分高。这叫**长度归一化**。

光看文字没有手感,下面的脚本把三条规矩分别量一遍,再手写一个完整的打分函数,和 `rank_bm25` 库对分数。新建 `part04/bm25_by_hand.py`:

```python
# agent-zero-lab/part04/bm25_by_hand.py
"""BM25 的三个因素分别看一眼,再手写一遍打分,和 rank_bm25 的结果对一对。"""
import math

from rank_bm25 import BM25Okapi

K1, B = 1.5, 0.75  # rank_bm25 的默认值

print("--- 因素一:词频饱和。文档长度等于平均长度时,出现 f 次的得分 = f*(k1+1)/(f+k1)")
for f in [0, 1, 2, 3, 5, 10, 20, 50]:
    print(f"  出现 {f:>2} 次  {f * (K1 + 1) / (f + K1):.3f}")

print("--- 因素二:逆文档频率。语料 42 块,词出现在 n 块里,idf = ln((N-n+0.5)/(n+0.5))")
for n in [1, 2, 5, 10, 20]:
    print(f"  出现在 {n:>2} 块  idf = {math.log((42 - n + 0.5) / (n + 0.5)):.3f}")

print("--- 因素三:长度归一化。同样出现 1 次,文档长度是平均长度的几倍,分数乘多少")
for ratio in [0.5, 1, 2, 4]:
    print(f"  长度 {ratio} 倍  {1 * (K1 + 1) / (1 + K1 * (1 - B + B * ratio)):.3f}")

print("--- 手写打分 vs rank_bm25")
docs = [
    ["退款", "退款", "年付", "比例"],
    ["退款", "月付", "不支持"],
    ["发票", "红冲", "开错", "重开"],
    ["错误码", "e1043", "编码", "utf-8"],
    ["错误码", "e1042", "日期", "格式", "模板", "导入", "失败", "列名"],
    ["套餐", "升级", "补差价"],
]
query = ["退款", "红冲"]


def my_bm25(docs: list[list[str]], query: list[str]) -> list[float]:
    n_docs = len(docs)
    avgdl = sum(len(d) for d in docs) / n_docs
    scores = []
    for d in docs:
        s = 0.0
        for term in query:
            n = sum(term in other for other in docs)  # 含这个词的文档数
            idf = math.log((n_docs - n + 0.5) / (n + 0.5))
            f = d.count(term)  # 这个词在本文档出现几次
            s += idf * f * (K1 + 1) / (f + K1 * (1 - B + B * len(d) / avgdl))
        scores.append(s)
    return scores


mine = my_bm25(docs, query)
theirs = BM25Okapi(docs, k1=K1, b=B).get_scores(query)
for i, (a, b) in enumerate(zip(mine, theirs)):
    print(f"  文档 {i}  手写 {a:.4f}  rank_bm25 {b:.4f}")
print("全部一致:", all(abs(a - b) < 1e-9 for a, b in zip(mine, theirs)))
```

<div class="line-notes">

- `import math` 标准库,要用 `math.log`(自然对数 ln)。
- `from rank_bm25 import BM25Okapi` 现成的 BM25 实现,Okapi 是最常用的那个版本。最后拿它来验证自己写的对不对。
- `K1, B = 1.5, 0.75` BM25 的两个可调参数。`k1` 管"词频饱和得多快",`b` 管"长度归一化打多重的折"。这两个值是 `rank_bm25` 的默认值,也是业界常用的起点。
- `for f in [0, 1, 2, 3, 5, 10, 20, 50]:` 因素一:词出现 `f` 次。
- `print(f"  出现 {f:>2} 次  {f * (K1 + 1) / (f + K1):.3f}")` 公式 `f × (k1+1) / (f + k1)`。代入 `f=1`:`1 × 2.5 / 2.5 = 1.000`;`f=2`:`2 × 2.5 / 3.5 = 1.429`;`f=20`:`20 × 2.5 / 21.5 = 2.326`;`f=50` 是 2.427。不管 `f` 多大,这个数最多逼近 `k1 + 1 = 2.5`,永远冲不过去,这就是"饱和"。
- `for n in [1, 2, 5, 10, 20]:` 因素二:这个词出现在 `n` 块里,语料一共 42 块。
- `math.log((42 - n + 0.5) / (n + 0.5))` IDF 的公式 `ln((N - n + 0.5) / (n + 0.5))`。`n=1` 时 `ln(41.5 / 1.5) = ln(27.67) = 3.320`;`n=20` 时 `ln(22.5 / 20.5) = 0.093`,几乎为零。`0.5` 是平滑项,防止 `n` 等于 0 或等于 N 时除零或取对数出错。
- `for ratio in [0.5, 1, 2, 4]:` 因素三:块的长度是全库平均长度的几倍。
- `1 * (K1 + 1) / (1 + K1 * (1 - B + B * ratio))` 词频固定为 1,看长度的影响。代入 `ratio=1`:分母 `1 + 1.5 × (0.25 + 0.75) = 2.5`,结果 `1.000`;`ratio=4`(长度是平均的 4 倍):`1 + 1.5 × (0.25 + 3) = 5.875`,结果 `2.5 / 5.875 = 0.426`。同样出现 1 次,长块的得分只有平均长度块的 43%。
- `docs = [` 六个"文档",每个是一个词列表,故意造得很小,好手算。
- `query = ["退款", "红冲"]` 要查的两个词。
- `def my_bm25(docs: list[list[str]], query: list[str]) -> list[float]:` 手写版。输入"每个文档的词列表"和"查询的词列表",输出每个文档的分数。
- `n_docs = len(docs)` 6。
- `avgdl = sum(len(d) for d in docs) / n_docs` 平均文档长度(avg doc length):各文档词数 4、3、4、4、8、3,总共 26,除以 6 得 4.33。
- `for d in docs:` 逐个文档算分。
- `for term in query:` 每个查询词算一份,最后相加。
- `n = sum(term in other for other in docs)` 有几个文档含这个词。`term in other` 是 `True/False`,`sum` 把 `True` 当 1。「退款」出现在文档 0、1,`n=2`;「红冲」只在文档 2,`n=1`。
- `idf = math.log((n_docs - n + 0.5) / (n + 0.5))` 「退款」`ln(4.5/2.5) = 0.588`,「红冲」`ln(5.5/1.5) = 1.299`。越稀罕越大。
- `f = d.count(term)` 这个词在这个文档里出现几次。文档 0 里「退款」出现 2 次。
- `s += idf * f * (K1 + 1) / (f + K1 * (1 - B + B * len(d) / avgdl))` 三个因素合在一起:IDF 乘以"饱和后的词频",分母里的 `len(d) / avgdl` 是长度归一化。代入文档 0 的「退款」:`0.588 × 2 × 2.5 / (2 + 1.5 × (0.25 + 0.75 × 4/4.33)) = 2.94 / 4.84 = 0.861`,和下面输出的文档 0 分数 `0.8610` 对上(「红冲」文档 0 没有,贡献 0)。
- `theirs = BM25Okapi(docs, k1=K1, b=B).get_scores(query)` 同样的输入交给库,返回 6 个分数的数组。
- `print("全部一致:", all(abs(a - b) < 1e-9 for a, b in zip(mine, theirs)))` 浮点数不能直接用 `==` 比,看差是否小于十亿分之一。`all(...)` 要求每个都成立。

三个因素的数字都在上面:出现 1 次得 1 分,出现 10 次也才 2.17 分,出现 50 次 2.43,饱和得很快;`E2017` 只出现在 2 块里,IDF 是 2.79,「导入」出现在 4 块里,IDF 是 2.15;一个 4 倍长的块,同样的词只值平均长度块的 43%。手写的 20 行,和库的输出小数点后 4 位完全一致,说明你已经把 BM25 的核心理解到位了。

第一次看公式的人容易觉得"为什么不直接数出现次数"。数次数有两个毛病:出现 50 次的长文会碾压专门讲这件事的短文(因素一和因素三解决),「的」「是」这类词会淹没真正有用的词(因素二解决)。BM25 就是在"数词"这个朴素想法上打的三个补丁。把三条规矩写成一个公式,是这样:

```text
score(D, Q) = Σ  IDF(q) × f(q,D) × (k1 + 1) / ( f(q,D) + k1 × (1 - b + b × |D| / avgdl) )
            q∈Q

f(q,D)   : 词 q 在文档 D 里出现的次数         → 第一条(词频饱和)
IDF(q)   : 包含 q 的文档越少,值越大           → 第二条(逆文档频率)
|D|/avgdl: 文档长度 / 全库平均长度            → 第三条(长度归一化)
k1 通常 1.2 到 2.0,b 通常 0.75
```

公式不用背,它就是 `my_bm25()` 里那一行 `s += ...`。`Σ` 是"对查询里的每个词求和"。

顺便说一个 `rank_bm25` 的小坑,练习 4 会演示:语料文档太少时,某个词出现在一半以上的文档里,IDF 会算出 0 甚至负数,分数就变成 0 或负的。我们有 42 块,碰不到,自己拿 2 篇文档测试时别以为代码写错了。

## 中文要先分词

BM25 数的是"词"。英文天然有空格,按空格一切就行;中文没有,「企业版年付中途取消能退多少」必须先切成词,BM25 才能数。分词切得好不好,直接决定 BM25 好不好。

Python 里最常用的中文分词库是 `jieba`(结巴)。新建 `part04/seg_demo.py`,看它切几个句子,再看 Postgres 自带的全文检索怎么对待同样的句子:

怎么办?**加业务词典**:把你们行业的术语告诉 `jieba`,用 `jieba.add_word("企业版")`。每个行业都有自己的术语,通用分词器一定会切错,真实项目里这份词表要从产品文档里抽、定期更新。

## 停用词

还有一类词也要处理:**停用词**(stop words),就是满大街都是、对区分文档没有帮助的词,「的」「了」「吗」「怎么办」。BM25 的 IDF 本来就会压低常见词的分数,为什么还要专门去掉?两个原因:一是去掉以后索引更小,二是——更重要的——**IDF 是看你的语料统计出来的,在一个很小的语料里,一个口语词可能碰巧很"稀罕"**。下面会看到这件事真的发生。

现在把分词、业务词典、停用词、BM25 拼成一个文件。新建 `part04/bm25_index.py`:

```python
# agent-zero-lab/part04/bm25_index.py
"""关键词检索:jieba 分词 + BM25。和向量检索互补,专治错误码、专有名词。"""
import logging
import re

import jieba
from rank_bm25 import BM25Okapi

from part04.chunking import Chunk, load_chunks

jieba.setLogLevel(logging.WARNING)

# 业务词典:jieba 不认识这些词,不加会被切碎(比如「企业版不限」会切成「企业」「版不限」)
BUSINESS_WORDS = [
    "免费版", "专业版", "企业版", "年付", "月付", "红冲", "自动续费", "宽限期", "冷静期",
    "两步验证", "多币种", "账本", "增值税专用发票", "验证器", "不适用于",
]
for _w in BUSINESS_WORDS:
    jieba.add_word(_w)

# 停用词:几乎每个问题都会带、对区分文档没有帮助的词。花括号里只有值,没有 key,这是集合 set。
STOPWORDS = {
    "的", "了", "是", "吗", "呢", "啊", "吧", "在", "和", "与", "及", "或", "我", "你", "我们", "你们",
    "怎么", "怎么办", "什么", "如何", "可以", "能", "还", "要", "就", "都", "也", "把", "被", "让", "会",
    "有", "没有", "一个", "时候", "报",
}
WORD = re.compile(r"\w+")  # \w 在 Python 里包含汉字、字母、数字、下划线;用来丢掉空格和标点


def tokenize(text: str, stopwords: set[str] = STOPWORDS) -> list[str]:
    """切词 → 丢掉空格标点 → 丢掉停用词 → 英文转小写。建索引和查询都走这一个函数。"""
    return [t.lower() for t in jieba.lcut(text) if WORD.fullmatch(t) and t not in stopwords]


class BM25Index:
    def __init__(self, chunks: list[Chunk], stopwords: set[str] = STOPWORDS):
        self.chunks = chunks
        self.stopwords = stopwords
        self.bm25 = BM25Okapi([tokenize(c.text, stopwords) for c in chunks])

    def search(self, query: str, k: int = 20) -> list[tuple[Chunk, float]]:
        """返回 (块, BM25 分数),分数从高到低,0 分的不返回。形状和 pg_store.search 一样。"""
        scores = self.bm25.get_scores(tokenize(query, self.stopwords))
        order = sorted(range(len(scores)), key=lambda i: -scores[i])[:k]
        return [(self.chunks[i], float(scores[i])) for i in order if scores[i] > 0]


if __name__ == "__main__":
    idx = BM25Index(load_chunks())
    print(f"建好了:{idx.bm25.corpus_size} 块,平均每块 {idx.bm25.avgdl:.2f} 个词")
    for q in ["导入时报 E2017", "E1043 是什么错误", "企业版年付中途取消能退多少", "买错了能把钱要回来吗"]:
        print(f"问:{q}  切成 {tokenize(q)}")
        hits = idx.search(q, 3)
        for c, s in hits:
            print(f"   {s:6.2f}  {c.id:<9}{c.title} > {c.section}")
        if not hits:
            print("   (一块都没有:所有词都没对上,42 块全是 0 分)")
```

<div class="line-notes">

- `import logging` 标准库的日志模块,下面用它给 `jieba` 调日志级别。
- `import re` 正则表达式库,下面用它判断"这个词是不是真正的词(不是空格和标点)"。
- `from part04.chunking import Chunk, load_chunks` Day 224 的块数据类和"读 data/kb/ 切块"函数。42 个块,每个有 `id`、`title`、`section`、`text` 等字段。
- `jieba.setLogLevel(logging.WARNING)` 把 `jieba` 的日志调到只打印警告以上,"Building prefix dict" 那四行就不再出现。
- `BUSINESS_WORDS = [` 业务词典,一个字符串列表。注意这里的词是我们对着 42 块文章整理的:免费版、专业版、企业版是套餐名;年付、月付、红冲、冷静期、宽限期是业务动作;「不适用于」是看到 `jieba` 把它切成「不适」「用于」后补的。
- `for _w in BUSINESS_WORDS:` 变量名以下划线开头,表示"这只是个临时变量,别的地方不会用"。
- `jieba.add_word(_w)` 把词加进 `jieba` 的全局词典,以后 `jieba.lcut` 遇到它们就会当一个整体。
- `STOPWORDS = {` 停用词集合,花括号里只有值没有键,所以是集合(Day 25)。用集合是因为 `t not in STOPWORDS` 对集合是常数时间,对列表要逐个比。
- `"怎么", "怎么办", "什么", "如何", "可以", "能",` 问句里常见的虚词。
- `"有", "没有", "一个", "时候", "报",` 最后这几个是我实测踩坑后加的,下面"没有它们会怎样"就是它们的故事。
- `WORD = re.compile(r"\w+")` 预编译一个正则。`\w` 在 Python 3 里匹配汉字、字母、数字和下划线,`\w+` 是"一个或多个"。`r"..."` 是原始字符串,反斜杠不用写两遍。
- `def tokenize(text: str, stopwords: set[str] = STOPWORDS) -> list[str]:` 切词函数,建索引和查询**都走它**,两边切法一致,BM25 才对得上。`stopwords` 做成可传的参数,下面做对比实验要用。
- `return [t.lower() for t in jieba.lcut(text) if WORD.fullmatch(t) and t not in stopwords]` 列表推导式,相当于 TS 的 `.filter(...).map(...)`。代入「导入的时候报 E1043」:`jieba.lcut` 得到 `['导入', '的', '时候', '报', ' ', 'E1043']`,`WORD.fullmatch(' ')` 是 `None`(空格不是 `\w`)所以去掉空格,「的」「时候」「报」都在停用词里,剩下 `['导入', 'E1043']`,最后 `.lower()` 把 `E1043` 变成 `e1043`,这样用户打小写 `e1043` 也能匹配。`fullmatch` 要求整个字符串都匹配,不是只匹配开头。
- `class BM25Index:` 一个类(Day 40),把"块列表"和"BM25 索引"绑在一起。
- `def __init__(self, chunks: list[Chunk], stopwords: set[str] = STOPWORDS):` 构造函数。建索引只跑一次。
- `self.chunks = chunks` 留着块列表,`search` 时要靠下标把分数换回块。
- `self.stopwords = stopwords` 记住用的是哪张停用词表,查询时同一张。
- `self.bm25 = BM25Okapi([tokenize(c.text, stopwords) for c in chunks])` 把 42 个块各自切好词,得到"42 个词列表"组成的列表,交给 `BM25Okapi`。它在内部把每个词的 IDF、每块的长度、全库平均长度都预先算好。实测建出来 `corpus_size = 42`,平均每块 26.90 个词。
- `def search(self, query: str, k: int = 20) -> list[tuple[Chunk, float]]:` 查询。返回 `(块, 分数)` 的列表,和 Day 232 的 `pg_store.search` 同一个形状,只是分数含义不同(BM25 原始分,不是 0 到 1 的相似度)。
- `scores = self.bm25.get_scores(tokenize(query, self.stopwords))` 返回一个长度 42 的 numpy 数组,第 `i` 个数是第 `i` 块的分数。
- `order = sorted(range(len(scores)), key=lambda i: -scores[i])[:k]` 对"下标 0 到 41"排序,排序依据是分数的负数(也就是从大到小),取前 `k` 个。`lambda i: -scores[i]` 是个一次性的小函数(Day 30),相当于 JS 的 `i => -scores[i]`。
- `return [(self.chunks[i], float(scores[i])) for i in order if scores[i] > 0]` 下标换回块,分数转成普通 float,0 分的丢掉(一个词都没对上)。
- `idx = BM25Index(load_chunks())` 脚本直接运行时的演示:读 42 块,建索引,一瞬间完成,不调任何接口。
- `print(f"建好了:{idx.bm25.corpus_size} 块,平均每块 {idx.bm25.avgdl:.2f} 个词")` `corpus_size` 和 `avgdl` 是 `BM25Okapi` 对象上的属性。
- `for q in ["导入时报 E2017",` 四个问题:前两个是向量盲区,第三个是业务词,第四个是"完全没字面重合"的口语。
- `print(f"问:{q}  切成 {tokenize(q)}")` 先打印切词结果,方便你看分词有没有问题。
- `print(f"   {s:6.2f}  {c.id:<9}{c.title} > {c.section}")` 分数占 6 格保留 2 位小数。
- `print("   (一块都没有:所有词都没对上,42 块全是 0 分)")` 没有命中时说明一下。

## 拆开一个分数看

到现在 BM25 的分数还是个黑盒。`rank_bm25` 对象上有我们要的全部中间量(每个词的 IDF、每块的词频和长度),可以把"导入时报 E2017"这个查询对 kb-012#1 的得分拆成每个词的贡献。新建 `part04/bm25_explain.py`:

```python
# agent-zero-lab/part04/bm25_explain.py
"""拆开看一个 BM25 分数:查询里每个词,在这一块里出现几次、idf 多大、各贡献多少分。"""
from part04.bm25_index import BM25Index, tokenize
from part04.chunking import load_chunks

idx = BM25Index(load_chunks())
bm = idx.bm25


def explain(query: str, chunk_id: str) -> None:
    i = next(n for n, c in enumerate(idx.chunks) if c.id == chunk_id)
    doc_freq = bm.doc_freqs[i]  # 这一块里每个词出现几次,一个字典
    length = bm.doc_len[i]
    print(f"问:{query}  块:{chunk_id}  这块有 {length} 个词(全库平均 {bm.avgdl:.2f})")
    total = 0.0
    for t in tokenize(query):
        f = doc_freq.get(t, 0)
        idf = bm.idf.get(t, 0.0)
        part = idf * f * (bm.k1 + 1) / (f + bm.k1 * (1 - bm.b + bm.b * length / bm.avgdl)) if f else 0.0
        total += part
        n_docs = sum(t in d for d in bm.doc_freqs)
        print(f"   {t:<8} 出现在 {n_docs:>2} 块里 idf={idf:5.2f}   本块出现 {f} 次   贡献 {part:5.2f}")
    print(f"   合计 {total:.2f}   rank_bm25 给的是 {bm.get_scores(tokenize(query))[i]:.2f}")


explain("导入时报 E2017", "kb-012#1")
explain("导入时报 E2017", "kb-009#1")
```

<div class="line-notes">

- `from part04.bm25_index import BM25Index, tokenize` 复用刚才写的。
- `idx = BM25Index(load_chunks())` 建好索引。
- `bm = idx.bm25` 给 `BM25Okapi` 对象起个短名字。它的几个属性今天会用到:`doc_freqs`(每块里每个词出现几次)、`doc_len`(每块多少个词)、`avgdl`、`idf`(每个词的 IDF)、`k1`、`b`。
- `def explain(query: str, chunk_id: str) -> None:` 输入查询和块编号,打印每个词的贡献。
- `i = next(n for n, c in enumerate(idx.chunks) if c.id == chunk_id)` 找到这个块在列表里的下标。`next(生成器)` 取第一个满足条件的。
- `doc_freq = bm.doc_freqs[i]` 第 `i` 块的词频字典,例如 `{'错误码': 2, 'e2017': 2, ...}`。
- `length = bm.doc_len[i]` 这一块的词数。kb-012#1 是 29。
- `for t in tokenize(query):` 对查询里的每个词算一份。
- `f = doc_freq.get(t, 0)` 词在这块里出现几次,没出现就是 0。`.get(键, 默认值)` 相当于 JS 的 `obj[key] ?? 0`。
- `idf = bm.idf.get(t, 0.0)` 这个词的 IDF。「时报」从没出现过,不在 `idf` 字典里,按 0 算。
- `part = idf * f * (bm.k1 + 1) / (f + bm.k1 * (1 - bm.b + bm.b * length / bm.avgdl)) if f else 0.0` 和 `my_bm25` 同一行公式。代入 kb-012#1 的 `e2017`:`2.79 × 2 × 2.5 / (2 + 1.5 × (0.25 + 0.75 × 29/26.9)) = 13.95 / 3.59 = 3.88`。
- `n_docs = sum(t in d for d in bm.doc_freqs)` 数有几块含这个词(`t in 字典` 判断的是键)。
- `print(f"   {t:<8} 出现在 {n_docs:>2} 块里` 每个词一行。
- `print(f"   合计 {total:.2f}   rank_bm25 给的是 {bm.get_scores(tokenize(query))[i]:.2f}")` 自己加出来的和库给的对照。
- `explain("导入时报 E2017", "kb-009#1")` 再解释一块:排在向量检索前三、却和 E2017 无关的 kb-009#1,看它为什么在 BM25 里得分低。

## 停用词表漏了会怎样

最后一件事,是我自己踩过的坑。`STOPWORDS` 里有两个很不起眼的词:「时候」和「报」。如果表里没有它们,问"导入的时候报 E1043"会怎样?新建 `part04/stopword_bug.py`,同一个问题,用"漏了这两个词的表"和"完整的表"各查一次:

```python
# agent-zero-lab/part04/stopword_bug.py
"""停用词表漏了口语词会怎样:同一个问题,分别用「少两个词的表」和「完整的表」检索。"""
import math

from part04.bm25_index import STOPWORDS, BM25Index, tokenize
from part04.chunking import load_chunks

chunks = load_chunks()
Q = "导入的时候报 E1043"
for label, sw in [("漏了「时候」「报」", STOPWORDS - {"时候", "报"}), ("完整停用词表", STOPWORDS)]:
    idx = BM25Index(chunks, sw)
    print(f"[{label}] 切成 {tokenize(Q, sw)}")
    for c, s in idx.search(Q, 3):
        print(f"   {s:5.2f}  {c.id:<9}{c.title} > {c.section}")

n_docs = len(chunks)
docs = [set(tokenize(c.text, set())) for c in chunks]
for term in ["时候", "e1043"]:
    n = sum(term in d for d in docs)
    print(f"「{term}」出现在 {n} 块里,idf = {math.log((n_docs - n + 0.5) / (n + 0.5)):.2f}")
```

<div class="line-notes">

- `import math` 下面要自己算 IDF。
- `from part04.bm25_index import STOPWORDS, BM25Index, tokenize` 把停用词表也导进来。
- `Q = "导入的时候报 E1043"` 一个典型的口语问法:"导入的时候"和"报"是口语,`E1043` 才是重点。
- `for label, sw in [("漏了「时候」「报」", STOPWORDS - {"时候", "报"}), ("完整停用词表", STOPWORDS)]:` 两张表对比。集合可以直接相减(Day 25):`STOPWORDS - {"时候", "报"}` 是"完整的表去掉这两个词"。

- `print(f"[{label}] 切成 {tokenize(Q, sw)}")` 看这张表下,问题被切成哪些词。
- `for c, s in idx.search(Q, 3):` 前 3 名。
- `docs = [set(tokenize(c.text, set())) for c in chunks]` 每块的"词集合"(`set()` 作为停用词表表示什么都不去掉),为的是数一个词出现在几块里。
- `for term in ["时候", "e1043"]:` 两个主角。
- `n = sum(term in d for d in docs)` 含这个词的块数。
- `math.log((n_docs - n + 0.5) / (n + 0.5))` IDF 公式,同 `bm25_by_hand.py`。

漏了两个词,排第一的是「自动续费与扣款规则 > 什么时候扣款」,一篇和错误码毫不相干的文章。原因看最后两行:「时候」在整个知识库里只出现在 1 块里(那块的标题恰好叫"什么时候扣款"),所以 IDF 是 3.32;而 `e1043` 出现在 2 块里,IDF 反而只有 2.79。一个口语虚词,因为在这个小语料里碰巧"稀罕",权重压过了错误码。完整的停用词表把「时候」和「报」去掉后,kb-011#1 回到第一。

这件事有三条教训。**停用词表不能网上抄一份就完事**:通用停用词表里没有「时候」,它在你的语料里却成了祸害。**语料越小越容易出这种事**,因为 IDF 是从语料里统计出来的,42 块里碰巧只出现一次的词,权重就很高。**要用真实的用户问题跑一跑**,看哪些口语词在捣乱,而不是只看自己写的"标准问法"。更彻底的办法是上线后记录用户的真实问题,统计高频口语词,定期更新停用词表。

## 小结:向量和 BM25 各管一半

| | 向量检索 | BM25 |
| --- | --- | --- |
| 怎么找 | 按意思(embedding 的距离) | 按字面(词的 IDF 和词频) |
| 擅长 | 同义改写、口语、"买错了能把钱要回来吗" | 错误码、型号、专有名词、"E2017" |
| 短板 | 必须一字不差的词;陌生字符串 | 同义词、说法不同("退钱"≠"退款")、错别字 |
| 成本 | 每个问题一次 embedding 调用 | 本机内存里算,毫秒级,不花钱 |
| 分数 | 余弦相似度,约在 0 到 1,有"低于就拒答"的阈值可用 | 原始分,只在同一个查询内有意义 |
| 要维护什么 | embedding 模型版本(换了要重算) | 分词、业务词典、停用词 |

两路结果怎么合成一份,是明天的事。分数不能直接相加(0.6 的相似度和 8.04 的 BM25 分不是同一个量纲),明天用一个只看名次的办法:RRF。

```python
from part04.chunking import load_chunks
```

```python
# agent-zero-lab/part04/ex_k1_b.py
"""练习 2:k1 和 b 怎么影响分数。同一个查询,换几组参数,看前 3 名和分数。"""
from rank_bm25 import BM25Okapi

from part04.bm25_index import tokenize
from part04.chunking import load_chunks

chunks = load_chunks()
corpus = [tokenize(c.text) for c in chunks]
Q = "企业版年付中途取消能退多少"
print("查询切成", tokenize(Q))
for k1, b in [(1.5, 0.75), (0.5, 0.75), (3.0, 0.75), (1.5, 0.0), (1.5, 1.0)]:
    scores = BM25Okapi(corpus, k1=k1, b=b).get_scores(tokenize(Q))
    top = sorted(range(len(chunks)), key=lambda i: -scores[i])[:3]
    print(f"k1={k1:<4} b={b:<5}", [(chunks[i].id, round(float(scores[i]), 2)) for i in top])
```

<div class="line-notes">

- `corpus = [tokenize(c.text) for c in chunks]` 先把 42 块切好,下面每组参数都重新用它建一次 `BM25Okapi`,不用重复切词。
- `for k1, b in [(1.5, 0.75), (0.5, 0.75), (3.0, 0.75), (1.5, 0.0), (1.5, 1.0)]:` 五组参数。第一组是默认值,第二第三组只动 `k1`(小:词频很快饱和;大:词频影响更久),第四第五组只动 `b`(0:完全不看长度;1:完全按长度折算)。

**练习 3:用户说"退钱",文档写"退款"。**BM25 对不上,想办法补上。

<details><summary>参考答案</summary>

最朴素的办法:一张同义词表,查询切完词以后,碰到表里的词就把它的同义词也加进去一起查(查询展开,query expansion)。新建 `part04/ex_synonym.py`:

```python
# agent-zero-lab/part04/ex_synonym.py
"""练习 3:用户说「退钱」「退费」,文档写「退款」,BM25 对不上。加一张同义词表,在查询这一侧展开。"""
from part04.bm25_index import BM25Index, tokenize
from part04.chunking import load_chunks

SYNONYMS = {"退钱": ["退款"], "退费": ["退款"], "返钱": ["退款"], "要回来": ["退款"]}
idx = BM25Index(load_chunks())


def search_expanded(query: str, k: int = 3):
    """切完词以后,把词表里有同义词的词,连同同义词一起拿去查。"""
    tokens = []
    for t in tokenize(query):
        tokens.append(t)
        tokens.extend(SYNONYMS.get(t, []))
    scores = idx.bm25.get_scores(tokens)
    order = sorted(range(len(scores)), key=lambda i: -scores[i])[:k]
    return tokens, [(idx.chunks[i].id, round(float(scores[i]), 2)) for i in order if scores[i] > 0]


for q in ["退款流程", "我要退钱", "怎么退费", "年付能不能退费"]:
    plain = [(c.id, round(s, 2)) for c, s in idx.search(q, 3)]
    tokens, expanded = search_expanded(q)
    print(f"问:{q}\n   不展开 {tokenize(q)} -> {plain}\n   展开后 {tokens} -> {expanded}")
```

<div class="line-notes">

- `SYNONYMS = {"退钱": ["退款"], "退费": ["退款"], "返钱": ["退款"], "要回来": ["退款"]}` 字典:用户的说法 → 文档里的标准说法列表。
- `idx = BM25Index(load_chunks())` 复用 `bm25_index.py` 的索引。
- `def search_expanded(query: str, k: int = 3):` 带展开的搜索。这里没写返回类型,返回 `(词列表, 前几名)`。
- `for t in tokenize(query):` 先照常切词。
- `tokens.append(t)` 原来的词保留。
- `tokens.extend(SYNONYMS.get(t, []))` 如果词表里有这个词,把它的同义词也加进去。`dict.get(键, [])` 没有就返回空列表。`extend` 一次追加多个。
- `scores = idx.bm25.get_scores(tokens)` 直接用 `BM25Okapi` 对象打分,绕过 `search()`,因为 `search()` 里切词是固定的。
- `order = sorted(range(len(scores)), key=lambda i: -scores[i])[:k]` 前 `k` 名的下标。
- `return tokens, [(idx.chunks[i].id, round(float(scores[i]), 2)) for i in order if scores[i] > 0]` 词列表和前几名。
- `plain = [(c.id, round(s, 2)) for c, s in idx.search(q, 3)]` 不展开的结果,用来对照。

## 名词解释

| 名词 | 意思 |
| --- | --- |
| 关键词检索 | 按"词有没有出现、出现多少"来找文档,不管意思。和向量检索(按意思)互补 |
| BM25 | 最常用的关键词检索打分公式,Elasticsearch 默认的相关性算法。名字里的 BM 是 Best Matching |
| 词频(TF) | 一个词在一篇文档里出现的次数 |
| 词频饱和 | 出现次数多了以后,多一次带来的加分越来越少,有上限。由 `k1` 控制 |
| 逆文档频率(IDF) | 一个词出现在越少的文档里,越有区分度,权重越大。`ln((N-n+0.5)/(n+0.5))` |
| 长度归一化 | 长文档里随便凑到一个词不算本事,长度超过平均就打折。由 `b` 控制 |
| `k1`、`b` | BM25 的两个可调参数,常用值 1.2 到 2.0 和 0.75 |
| 分词 | 把一句话切成一个个词。英文按空格,中文要用分词库(如 jieba) |
| jieba | 最常用的 Python 中文分词库。不认识的业务词会切碎,要加自定义词典 |
| 业务词典 | 自己整理的、通用分词器不认识的词表,`jieba.add_word(...)` 加进去 |
| 停用词 | 满大街都是、对区分文档没帮助的词(「的」「了」「怎么办」),建索引和查询时都去掉 |
| 查询展开 | 查询时把词的同义词一起加进去查,补字面不一致的缺口 |
| `tsvector` | Postgres 内置全文检索用的类型,存"切好的词和位置"。默认配置不会切中文 |
| `SyntaxWarning` | Python 编译源码时对可疑写法的警告,不影响运行;`.pyc` 缓存生成后不会再出现 |

## 常见误区

**以为向量检索什么都能找到。** 它对错误码、型号、人名这类必须一字不差的词很弱(今天"导入时报 E2017",真正的那块排第 7)。关键词检索不是过时的技术,是补短板的。

**用 BM25 之前不分词。** 把整句中文当一个词去匹配,几乎什么都匹配不上。英文才能按空格切。

**用 `jieba` 默认词典就上线。** 业务词会被切碎(「企业」「版年付」)。要从产品文档里抽术语建词典,新增产品名、套餐名时同步更新。

**停用词表在网上抄一份就算完。** 今天实测,没有「时候」「报」两个词,问"导入的时候报 E1043"第一名是讲扣款时间的文章。停用词要拿真实的用户问题跑一遍验证。

**建索引和查询用了不同的切词方式。** 一边加了业务词典、一边没加,切出来的词不一致,BM25 就对不上。让两边走同一个 `tokenize()` 函数。

**拿 BM25 的分数设阈值,或者和向量相似度直接比较。** BM25 分数只在同一个查询内有意义(练习 5:第一名分数从 3.43 到 20.58)。

**拿两三篇文档测试 BM25,分数是负的就以为写错了。** 词出现在一半以上的文档里,IDF 为负,`rank_bm25` 又做了特殊处理,结果可能是 0 或者负数。小测试至少用十篇以上的文档。

**把 Python 的 `SyntaxWarning` 当成错误。** `jieba` 第一次导入时的三条警告是它源码的问题,不影响结果,第二次运行就没了。

## 自测

**1. BM25 的三个因素分别解决什么问题?**

<details><summary>答案</summary>

词频饱和:一个词出现 20 次和 21 次没有差别,防止重复堆词的长文碾压;IDF:出现得越少的词越重要,让「E2017」比「的」有分量;长度归一化:长文随便凑到一个词不算数,长度超过平均就打折。

</details>

**2. 为什么不能把整句中文直接交给 BM25?**

<details><summary>答案</summary>

BM25 数的是"词"。中文没有空格,整句话会被当作一个词,几乎不可能和文档里的任何东西匹配。必须先分词(今天用 jieba),并且建索引和查询两边用同一套切法。

</details>

**3. 实验:漏掉「时候」「报」两个停用词,问"导入的时候报 E1043",为什么排第一的变成了讲扣款时间的文章?**

<details><summary>答案</summary>

IDF 是从语料里统计出来的。42 块里「时候」只出现在 1 块(标题"什么时候扣款"),IDF 是 3.32;`e1043` 出现在 2 块里,IDF 只有 2.79。口语虚词因为碰巧稀罕,权重压过了错误码。完整的停用词表把它们去掉就恢复了。教训:停用词表要拿真实的问题验证,语料越小越容易出这种事。

</details>

**4. 向量检索和 BM25 各自最擅长、最不擅长什么?**

<details><summary>答案</summary>

向量检索擅长同义改写和口语("买错了能把钱要回来吗"能找到退款政策),不擅长必须一字不差的词(错误码 E2017 排到第 7)。BM25 反过来:对错误码、型号、专有名词精确命中,对说法不同("退钱"对"退款")完全无能为力,要靠同义词表等办法补。两者互补。

</details>

**5. 面试题:你的知识库问答里,用户常常搜错误码,效果不好。你怎么排查和改进?**

<details><summary>答案</summary>

先确认是不是向量检索的盲区:拿一批带错误码的真实问题,看正确答案的名次(今天实测向量把 E2017 排第 7,BM25 排第 1)。改进:加一路 BM25 关键词检索,和向量检索的结果合并(明天讲 RRF);BM25 要做好中文分词、业务词典和停用词,并且用真实问题验证停用词表;可以在块里加上结构化字段(比如把错误码写进标题,今天的数据就是这样做的)。再用一组标好答案的评测题对比"只向量""只 BM25""混合"三种,以数据说话。

</details>

**6. BM25 的分数能不能像余弦相似度一样设阈值,"低于多少就拒答"?**

<details><summary>答案</summary>

不能。BM25 分数取决于查询里有几个词、这些词的稀有程度、块的长度,只在同一个查询内有可比性。今天 17 个问题的第一名分数从 3.43 到 20.58,而且 3.43 那条是答对的。需要拒答判断时,用向量相似度,或者专门的重排序模型(后面会学)。

</details>
