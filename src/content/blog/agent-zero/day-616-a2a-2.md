## 上一课回顾

[Day 614](/blog/agent-zero/day-614-a2a-1/) 用一个纯本地的模拟看清了「对面是工具」和「对面是 Agent」的区别:Agent 不透明、任务有状态、会反问你,到了终态就不能再动;还把 MCP、A2A、Agent Client Protocol 三个协议各连哪一段分清,并查到 A2A 规范 1.0 在 2026 年 3 月 12 日发布。[Day 615](/blog/agent-zero/day-615-week88-review/) 复习时顺手揪出了 614 那个 `FinanceAgent` 的一个 bug:任务还在 working 时再发一条消息,它会再起一份对账。

那个 `FinanceAgent` 是我们自己写的玩具,状态名也是照着规范的意思随手取的。今天换成真的:用官方 Python SDK 把同一个对账 Agent 做成一个 A2A 服务,让客户端从网络上去调它。这样规范里那些对象,你都能在真实的请求和响应里看到。

## 今天要解决的问题

学完今天你应该能:

1. 用 `a2a-sdk` 起一个 A2A 服务、写一个客户端,并在真实输出里指出 Agent Card、Task、Message、Artifact、Part 五个对象各是哪一块。

## 第 1 步:把对账 Agent 做成真的 A2A 服务

Day 614 的对账 Agent 有三个行为:没发票号就反问、有发票号就开工、做完给结果。照样来一遍,只是这回用 SDK 的接口写。SDK 的思路是你实现一个 `AgentExecutor`(执行器),它只管「收到一条消息后该往外报告什么事件」,HTTP 路由、任务存储、状态流转都归 SDK。

```python
# agent-zero-lab/part10/a2a/finance_server.py
"""用官方 a2a-sdk 把 Day 614 的对账 Agent 做成真的 A2A 服务。规则写死,不调模型。"""
import asyncio
import re

import uvicorn
from a2a.helpers import get_message_text, new_data_part, new_task_from_user_message, new_text_message
from a2a.server.agent_execution import AgentExecutor, RequestContext
from a2a.server.events import EventQueue
from a2a.server.request_handlers import DefaultRequestHandler
from a2a.server.routes import create_agent_card_routes, create_jsonrpc_routes
from a2a.server.tasks import InMemoryTaskStore, TaskUpdater
from a2a.types import AgentCapabilities, AgentCard, AgentInterface, AgentSkill
from starlette.applications import Starlette

PORT = 9101
INVOICE = re.compile(r"INV-\d{4}-\d{2}")


class FinanceExecutor(AgentExecutor):
    async def execute(self, context: RequestContext, event_queue: EventQueue) -> None:
        assert context.message is not None
        task = context.current_task
        if task is None:
            task = new_task_from_user_message(context.message)
            await event_queue.enqueue_event(task)
        updater = TaskUpdater(event_queue, task.id, task.context_id)

        text = get_message_text(context.message)
        hit = INVOICE.search(text)
        if hit is None:
            await updater.requires_input(new_text_message("请提供发票号(INV-0000-00 这种格式)"))
            return

        await updater.start_work(new_text_message(f"开始对账 {hit.group()}"))
        await asyncio.sleep(0.3)  # 假装查账、对合同
        result = {"invoice": hit.group(), "finding": "重复扣款", "amount_cny": 1200, "action": "已发起退款"}
        await updater.add_artifact(parts=[new_data_part(result)], name="reconcile-result")
        await updater.complete(new_text_message("对账完成"))

    async def cancel(self, context: RequestContext, event_queue: EventQueue) -> None:
        raise NotImplementedError("这个对账 Agent 不支持取消")


def build_card() -> AgentCard:
    skill = AgentSkill(
        id="reconcile_invoice",
        name="发票对账",
        description="按发票号核对扣款记录和合同,找重复扣款、金额不符。",
        tags=["finance", "billing"],
        examples=["帮我核对一下 INV-0042-03"],
        input_modes=["text/plain"],
        output_modes=["application/json"],
    )
    return AgentCard(
        name="Finance Reconcile Agent",
        description="财务团队的对账 Agent",
        version="0.1.0",
        default_input_modes=["text/plain"],
        default_output_modes=["application/json"],
        capabilities=AgentCapabilities(streaming=True),
        supported_interfaces=[
            AgentInterface(protocol_binding="JSONRPC", url=f"http://127.0.0.1:{PORT}/", protocol_version="1.0")
        ],
        skills=[skill],
    )


def build_app() -> Starlette:
    card = build_card()
    handler = DefaultRequestHandler(
        agent_executor=FinanceExecutor(), task_store=InMemoryTaskStore(), agent_card=card
    )
    routes = [*create_agent_card_routes(card), *create_jsonrpc_routes(handler, "/")]
    return Starlette(routes=routes)


if __name__ == "__main__":
    uvicorn.run(build_app(), host="127.0.0.1", port=PORT, log_level="warning")
```

<div class="line-notes">

- `INVOICE = re.compile(` 用正则判断消息里有没有发票号。Day 614 里是 `"INV-" in h`,这里严格一点:`INV-` 加四位数字、横线、两位数字。`INV-0042-03` 能匹配,`INV-42` 不能。`re.compile` 把正则预编译成对象,相当于 JS 里的 `/INV-\d{4}-\d{2}/`。
- `class FinanceExecutor(AgentExecutor):` 执行器基类。你只需要实现 `execute` 和 `cancel` 两个方法。
- `async def execute(` SDK 每收到一条 `SendMessage`,就调一次它。注意它不返回值,所有结果都通过第二个参数 `event_queue` 往外发事件,事件类型就是任务、状态更新、产出物。这就是 A2A「任务有状态」在代码里的样子。
- `assert context.message is not None` `context.message` 是这次收到的用户消息。类型上它可能是空,断言一下让类型检查器闭嘴,也让真出了怪事时立刻报错。
- `task = context.current_task` 如果这条消息带了 `taskId`,SDK 会按 id 把已有的任务取出来放在这里;第一条消息没有 id,这里就是 `None`。
- `task = new_task_from_user_message(context.message)` 新建任务。SDK 帮你生成任务 id 和 contextId(UUID),并把这条用户消息记进任务历史。
- `await event_queue.enqueue_event(task)` 把新任务发给 SDK,SDK 才会把它存进任务库,并回复给客户端。只创建不发,客户端永远收不到。
- `updater = TaskUpdater(` `TaskUpdater` 是 SDK 提供的小助手,帮你把「状态变成 working」「加一个产出物」这类动作翻译成事件发出去。三个参数:队列、任务 id、contextId。
- `hit = INVOICE.search(text)` 在用户消息文字里找发票号。代入 `帮我核对一下 INV-0042-03`,`hit.group()` 就是 `INV-0042-03`;代入 `客户 C-0042 说上个月被扣了两次钱`,找不到,`hit` 是 `None`。
- `await updater.requires_input(` 没找到发票号就把任务状态改成 `TASK_STATE_INPUT_REQUIRED`,同时带一句话问客户端。然后 `return`,执行器就结束了。任务没结束,只是停在「等你补信息」。
- `await updater.start_work(` 状态改成 `TASK_STATE_WORKING`,附一句「开始对账 INV-0042-03」。客户端如果订阅了流,这时就能收到这个中间状态。
- `await asyncio.sleep(0.3)` 假装去查了账、对了合同。真实的对账 Agent 可能要几分钟。
- `await updater.add_artifact(` 把结果作为**产出物**加进任务。`new_data_part(result)` 做了一个「结构化数据」类型的 Part,里面是一个字典。`name="reconcile-result"` 给产出物起个名字。
- `await updater.complete(` 任务状态改成 `TASK_STATE_COMPLETED`,这是终态。从这之后,同一个任务 id 再发消息会被 SDK 拒绝。
- `async def cancel(` 取消钩子。这个对账 Agent 不支持取消,直接抛 `NotImplementedError`。我实测过:调用方发 `CancelTask`,拿到的是 `{"code": -32603, "message": "这个对账 Agent 不支持取消"}`,也就是 SDK 把异常包成了 JSON-RPC 的「内部错误」。这不是规范里标准的「任务不可取消」错误,所以练习 1 会把它做出来。
- `def build_card() -> AgentCard:` 名片就是一个数据对象,不是代码逻辑。
- `skill = AgentSkill(` 技能。`id` 是机器看的标识,`description` 和 `examples` 是给调用方(通常是另一个 Agent 的大模型)读的,决定它会不会把活派给你。
- `capabilities=AgentCapabilities(streaming=True)` 声明「我支持流式」。声明了就得真的支持:SDK 的 JSON-RPC 路由已经帮你实现了流式。
- `supported_interfaces=[` 1.0 里「去哪里调我」是一个数组,每一项写 URL、传输绑定、协议版本。Day 614 查到的发布记录里说过,0.3 时代的 `preferredTransport` 和 `additionalInterfaces` 合并成了它。
- `AgentInterface(protocol_binding="JSONRPC"` 这一项说:在 `http://127.0.0.1:9101/` 用 JSON-RPC 绑定、1.0 版本调我。规范要求生产环境这里必须是 https,本地演示才用 http。
- `def build_app() -> Starlette:` 把执行器、任务库、名片、路由组装成一个 Web 应用。
- `handler = DefaultRequestHandler(` SDK 的默认请求处理器。它拿着你的执行器和任务库,负责处理 `SendMessage`、`GetTask`、`CancelTask` 这些操作。`InMemoryTaskStore` 把任务存在内存里,进程一重启就丢,生产环境要换成数据库版。
- `routes = [` 两组路由:`create_agent_card_routes` 在 `/.well-known/agent-card.json` 提供名片,`create_jsonrpc_routes(handler, "/")` 在根路径 `/` 接 JSON-RPC 请求。
- `uvicorn.run(` 启动服务,监听本机 9101 端口。`log_level="warning"` 让终端安静一点。

</div>

### 我第一版写错了什么

上面的代码是改过的。我第一版在产出物那一行写的是 `parts=[new_data_artifact(result).parts[0]]`,看起来也说得通:造一个数据产出物,取它的第一个 Part。结果客户端跑到第二步直接报错:

```text
a2a.utils.errors.InternalError: new_data_artifact() missing 1 required positional argument: 'data'
```

原因是 `new_data_artifact` 的参数是 `(name, data)`,我只传了 `result`,它把 `result` 当成了 `name`。Python 不会在写代码时拦你,一直到这一行被执行才报错;而这一行只有在客户端补完发票号之后才会执行,所以第一轮「反问」完全正常,第二轮才炸。另外值得学的一点:服务端的异常没有让服务崩掉,SDK 把它包成 JSON-RPC 的 `InternalError` 返回给了客户端。改法是直接用 `new_data_part(result)` 造 Part,不用绕产出物这一层。

## 第 2 步:客户端和五个核心对象

现在写客户端。SDK 的客户端会先读名片、挑一个自己也支持的传输绑定,再发请求。

```python
# agent-zero-lab/part10/a2a/client_basic.py
"""最小 A2A 客户端:读名片 → 发消息 → 被反问 → 同一个任务里补信息 → 拿到产出物。"""
import asyncio

import httpx
from a2a.client import A2ACardResolver, ClientConfig, create_client
from a2a.helpers import get_data_parts, get_message_text, new_text_message
from a2a.types import Role, SendMessageRequest, TaskState

BASE = "http://127.0.0.1:9101"


async def main() -> None:
    async with httpx.AsyncClient() as http:
        card = await A2ACardResolver(httpx_client=http, base_url=BASE).get_agent_card()
    print("名片:", card.name, "| 技能:", [s.id for s in card.skills])

    client = await create_client(agent=card, client_config=ClientConfig(streaming=False))

    msg = new_text_message("客户 C-0042 说上个月被扣了两次钱,帮忙核对", role=Role.ROLE_USER)
    replies = [r async for r in client.send_message(SendMessageRequest(message=msg))]
    task = replies[-1].task  # 非流式只会有一个响应
    print("第 1 轮:", TaskState.Name(task.status.state), "|", get_message_text(task.status.message))

    follow = new_text_message("发票号 INV-0042-03", role=Role.ROLE_USER)
    follow.task_id = task.id
    follow.context_id = task.context_id
    replies = [r async for r in client.send_message(SendMessageRequest(message=follow))]
    task = replies[-1].task
    print("第 2 轮:", TaskState.Name(task.status.state))
    for art in task.artifacts:
        print("产出物:", art.name, get_data_parts(art.parts))
    print("历史条数:", len(task.history))
    await client.close()


if __name__ == "__main__":
    asyncio.run(main())
```

<div class="line-notes">

- `BASE = "http://127.0.0.1:9101"` 服务的地址,和 `finance_server.py` 里的 `PORT` 对应。
- `async with httpx.AsyncClient() as http:` 开一个 HTTP 客户端读名片。`async with` 保证用完自动关闭连接,相当于 JS 里 `try { ... } finally { client.close() }`。
- `card = await A2ACardResolver(` 解析器自己去拼 `BASE + /.well-known/agent-card.json` 并下载、解析成 `AgentCard` 对象。你不用自己写路径。
- `client = await create_client(agent=card` 按名片创建客户端。它读 `supportedInterfaces`,只找到 JSON-RPC 一项,就用 JSON-RPC。`streaming=False` 表示不要流,一次请求拿一次完整响应。
- `msg = new_text_message(` 造一条用户消息:`Role.ROLE_USER` 表示「来自客户端」。这条消息里没有发票号,所以服务端会反问。
- `replies = [r async for r in client.send_message(` `send_message` 是个异步生成器(开了流的话会逐个吐事件),所以用异步列表推导把它收完。非流式只会有一个响应。
- `task = replies[-1].task` 响应是一个 `StreamResponse`,里面可能装 `task`、`message`、`status_update`、`artifact_update` 之一。对一个有状态的 Agent,第一个响应通常是 `task`。
- `TaskState.Name(task.status.state)` protobuf 枚举的数字转名字,代入实际值就是 `TASK_STATE_INPUT_REQUIRED`。
- `follow.task_id = task.id` 想在**同一个任务**里继续说,就得把上一轮的 `task.id` 填进新消息的 `task_id`,再填上 `context_id`。不填的话服务端会当成新任务,再反问一次。
- `get_data_parts(art.parts)` 取出产出物里「结构化数据」类型的 Part。我们服务端放进去的是字典,这里就能拿回字典。
- `print("历史条数:", len(task.history))` 任务历史里累计了几条消息。代入我这次的实际输出是 4:你的两条,加上服务端两条状态消息(反问那条、开始对账那条)。

对着输出,五个核心对象可以一一指出来。

**Agent Card** 是第一行读到的名片。**Task** 是 `task` 变量,它有 `id`、`context_id`(把相关的多个任务归到同一次会话)、`status`(状态加一条说明消息)、`artifacts`(产出物)和 `history`(历史消息)。**Message** 是你发的 `msg` 和服务端放在 `status.message` 里的那句话,`role` 只有两种,`ROLE_USER` 是客户端说的,`ROLE_AGENT` 是服务端说的。**Artifact** 是任务做完后交付的东西,这里是名字叫 `reconcile-result` 的那份对账结果。**Part** 是内容的最小单位,Message 和 Artifact 都是一串 Part 拼成的。1.0 里 Part 有四种内容:文本 `text`、二进制 `raw`、指向文件的 `url`、任意结构化数据 `data`。

Message 和 Artifact 的分工经常被问到:Message 是沟通过程(「请提供发票号」「开始对账」),Artifact 是交付结果。同一个任务里可以有很多条 Message,但交付物应该放进 Artifact,这样调用方不用从聊天记录里捞结果。

### 任务的九个状态

状态机在 Day 614 的模拟里你已经感受过了。规范 1.0 的 `a2a.proto` 里一共定义了这些状态(我对着 1.0.1 的文件数过):

| 状态 | 是不是终态 | 什么时候出现 |
| --- | --- | --- |
| `TASK_STATE_SUBMITTED` | 否 | 任务刚收下 |
| `TASK_STATE_WORKING` | 否 | 正在干活 |
| `TASK_STATE_INPUT_REQUIRED` | 否(中断) | 要调用方补信息,补完在同一任务里继续 |
| `TASK_STATE_AUTH_REQUIRED` | 否(中断) | 干到一半发现需要额外授权,比如要代表用户去读他的邮箱 |
| `TASK_STATE_COMPLETED` | 是 | 做完了 |
| `TASK_STATE_FAILED` | 是 | 出错了 |
| `TASK_STATE_CANCELED` | 是 | 被调用方取消 |
| `TASK_STATE_REJECTED` | 是 | 对方判断「这活我不接」(比如发票不归这个客户) |

加上 `TASK_STATE_UNSPECIFIED` 一共九个,最后这个只是占位。规范要求:往终态任务里再发消息,必须返回 `UnsupportedOperationError`,和 Day 614 模拟里「终态不能再动」是同一条规则。

还有一个今天不展开、但值得知道的开关:`SendMessageConfiguration` 里的 `return_immediately`。默认(`false`)时,`SendMessage` 会一直等到任务进入终态或中断状态才返回,所以我们的客户端一次请求就拿到了 `COMPLETED`。设成 `true`,服务端建好任务就立刻返回,调用方自己轮询或订阅。练习 1 会用到它。

## 第 3 步:线上到底传了什么,以及三种传输绑定

SDK 把一切藏得很好,但排查问题时你迟早要看原始请求。下面不用 SDK,直接用 `httpx` 手发 JSON-RPC 请求,顺带试几种版本头。

```python
# agent-zero-lab/part10/a2a/wire_jsonrpc.py
"""不用 SDK,直接用 httpx 发 JSON-RPC,看线上到底传了什么,再试三种版本头。"""
import json
import uuid

import httpx

URL = "http://127.0.0.1:9101/"


def rpc(method: str, params: dict, version: str | None = "1.0") -> dict:
    headers = {"A2A-Version": version} if version else {}
    body = {"jsonrpc": "2.0", "id": 1, "method": method, "params": params}
    return httpx.post(URL, json=body, headers=headers, timeout=10).json()


def user_message(text: str, task_id: str | None = None) -> dict:
    msg = {"messageId": str(uuid.uuid4()), "role": "ROLE_USER", "parts": [{"text": text}]}
    if task_id:
        msg["taskId"] = task_id
    return {"message": msg}


print("--- 1.0 格式,带 A2A-Version: 1.0 ---")
r = rpc("SendMessage", user_message("帮我核对一下 INV-0042-03"))
print(json.dumps(r, ensure_ascii=False, indent=1))
task_id = r["result"]["task"]["id"]

print("\n--- 往终态任务再发一条 ---")
print(json.dumps(rpc("SendMessage", user_message("再看看 INV-0042-04", task_id)), ensure_ascii=False))

print("\n--- 版本头写 9.9 ---")
print(json.dumps(rpc("SendMessage", user_message("INV-0042-03"), version="9.9"), ensure_ascii=False))

print("\n--- 不带版本头,方法名还是 1.0 的 ---")
print(json.dumps(rpc("SendMessage", user_message("INV-0042-03"), version=None), ensure_ascii=False))

print("\n--- 带 0.3 的方法名 message/send ---")
print(json.dumps(rpc("message/send", user_message("INV-0042-03"), version="0.3"), ensure_ascii=False))
```

<div class="line-notes">

- `URL = "http://127.0.0.1:9101/"` JSON-RPC 绑定的入口,就是名片里 `supportedInterfaces[0].url`。
- `def rpc(method: str, params: dict, version: str | None = "1.0") -> dict:` 封装一次 JSON-RPC 调用。`version` 默认 `"1.0"`,传 `None` 表示不带版本头。
- `headers = {"A2A-Version": version} if version else {}` **客户端每次请求都要带 `A2A-Version`**,值只写主次版本号(`1.0`,不写 `1.0.1`)。
- `body = {"jsonrpc": "2.0", "id": 1, "method": method, "params": params}` JSON-RPC 2.0 的固定信封:`method` 是操作名,`params` 是参数。1.0 里操作名是驼峰的 `SendMessage`,0.3 时代是 `message/send`。
- `"role": "ROLE_USER"` 1.0 的枚举值一律是带前缀的全大写加下划线,0.3 时代的写法是 `"user"`。同一行的 `"parts": [{"text": text}]` 也变了:1.0 里 Part 不再有 `kind` 字段,看对象里有哪个字段(这里是 `text`)就知道是什么类型。
- `r = rpc("SendMessage", user_message("帮我核对一下 INV-0042-03"))` 这条消息带发票号,所以服务端直接开工,等做完才返回。
- `task_id = r["result"]["task"]["id"]` 响应的结构是 `result.task`;如果是个直接回复的 Message,就是 `result.message`。
- `rpc("SendMessage", user_message("再看看 INV-0042-04", task_id))` 往已经 completed 的任务里再发消息。
- `version="9.9"` 故意写一个服务端肯定不支持的版本。
- `version=None` 不带版本头。规范写得很清楚:没有这个头的话,服务端当成 0.3。
- `rpc("message/send", user_message("INV-0042-03"), version="0.3")` 用 0.3 的方法名去调只开了 1.0 的服务端。

</div>

### 同一个 Agent,换两种绑定

规范 1.0 把「语义」和「怎么传」分开:同一套操作,可以通过三种**传输绑定**(protocol binding)提供:JSON-RPC、gRPC、HTTP+JSON(REST 风格)。名片的 `supportedInterfaces` 里每一项声明一种。gRPC 是 Google 的二进制 RPC 协议,要装额外的依赖,今天不跑;我们用同一个对账 Agent 同时开 JSON-RPC 和 REST。

```python
# agent-zero-lab/part10/a2a/finance_multi.py
"""同一个对账 Agent,同时开 JSON-RPC 和 HTTP+JSON(REST)两种绑定,并打开 0.3 兼容。"""
import uvicorn
from a2a.server.request_handlers import DefaultRequestHandler
from a2a.server.routes import create_agent_card_routes, create_jsonrpc_routes, create_rest_routes
from a2a.server.tasks import InMemoryTaskStore
from a2a.types import AgentInterface
from starlette.applications import Starlette

from part10.a2a.finance_server import FinanceExecutor, build_card

PORT = 9102


def build_app() -> Starlette:
    card = build_card()
    del card.supported_interfaces[:]
    card.supported_interfaces.extend(
        [
            AgentInterface(protocol_binding="JSONRPC", url=f"http://127.0.0.1:{PORT}/rpc", protocol_version="1.0"),
            AgentInterface(protocol_binding="HTTP+JSON", url=f"http://127.0.0.1:{PORT}/rest", protocol_version="1.0"),
        ]
    )
    handler = DefaultRequestHandler(agent_executor=FinanceExecutor(), task_store=InMemoryTaskStore(), agent_card=card)
    routes = [
        *create_agent_card_routes(card),
        *create_jsonrpc_routes(handler, "/rpc", enable_v0_3_compat=True),
        *create_rest_routes(handler, enable_v0_3_compat=True, path_prefix="/rest"),
    ]
    return Starlette(routes=routes)


if __name__ == "__main__":
    uvicorn.run(build_app(), host="127.0.0.1", port=PORT, log_level="warning")
```

<div class="line-notes">

- `from part10.a2a.finance_server import FinanceExecutor, build_card` 直接复用第 1 步的执行器和名片,一行业务代码都不重写。这说明传输绑定只是「皮」,执行器不在乎。
- `PORT = 9102` 换一个端口,免得和 9101 的那个服务冲突。
- `del card.supported_interfaces[:]` protobuf 的数组字段不能直接赋值,先清空再 `extend`。
- `AgentInterface(protocol_binding="JSONRPC", url=f"http://127.0.0.1:{PORT}/rpc"` 第一项:JSON-RPC,放在 `/rpc`。名片里排在前面的是服务端偏好的。
- `AgentInterface(protocol_binding="HTTP+JSON"` 第二项:REST 风格,放在 `/rest`。
- `create_jsonrpc_routes(handler, "/rpc", enable_v0_3_compat=True)` 打开 0.3 兼容开关:同一个 URL 同时认 1.0 和 0.3 的请求。
- `create_rest_routes(handler, enable_v0_3_compat=True, path_prefix="/rest")` REST 绑定的路由,同样开 0.3 兼容,所有路径前面加 `/rest`。

</div>

```python
# agent-zero-lab/part10/a2a/bindings_compare.py
"""同一个问题,走 JSON-RPC、走 REST、开流式,再用 0.3 的老格式发一次,对比拿到的东西。"""
import asyncio

import httpx
from a2a.client import A2ACardResolver, ClientConfig, create_client
from a2a.helpers import new_text_message
from a2a.types import Role, SendMessageRequest, TaskState

BASE = "http://127.0.0.1:9102"
QUESTION = "帮我核对一下 INV-0042-03"


async def via(binding: str, streaming: bool) -> None:
    async with httpx.AsyncClient() as http:
        card = await A2ACardResolver(httpx_client=http, base_url=BASE).get_agent_card()
    cfg = ClientConfig(streaming=streaming, supported_protocol_bindings=[binding])
    client = await create_client(agent=card, client_config=cfg)
    req = SendMessageRequest(message=new_text_message(QUESTION, role=Role.ROLE_USER))
    kinds = []
    async for resp in client.send_message(req):
        which = resp.WhichOneof("payload")
        if which == "status_update":
            which += ":" + TaskState.Name(resp.status_update.status.state).removeprefix("TASK_STATE_")
        kinds.append(which)
    print(f"{binding:10} streaming={streaming!s:5} -> 收到 {len(kinds)} 个响应:{kinds}")
    await client.close()


def old_03() -> None:
    body = {"jsonrpc": "2.0", "id": 1, "method": "message/send",
            "params": {"message": {"messageId": "m3", "role": "user", "kind": "message",
                                   "parts": [{"kind": "text", "text": QUESTION}]}}}
    r = httpx.post(f"{BASE}/rpc", json=body, timeout=10).json()["result"]
    print("0.3 老格式 -> kind =", r["kind"], "| state =", r["status"]["state"], "| part.kind =", r["artifacts"][0]["parts"][0]["kind"])


async def main() -> None:
    await via("JSONRPC", False)
    await via("HTTP+JSON", False)
    await via("JSONRPC", True)
    old_03()


asyncio.run(main())
```

<div class="line-notes">

- `BASE = "http://127.0.0.1:9102"` 这回连的是多绑定的那个服务。
- `async def via(binding: str, streaming: bool) -> None:` 参数决定用哪种绑定、要不要流式。
- `cfg = ClientConfig(streaming=streaming, supported_protocol_bindings=[binding])` 客户端偏好。SDK 文档写的是「留空就只用 JSON-RPC」,所以想走 REST 必须在这里写 `["HTTP+JSON"]`。
- `which = resp.WhichOneof("payload")` 响应是 protobuf 的 `oneof`:任务、消息、状态更新、产出物更新四选一,`WhichOneof` 问它当前装的是哪一个。
- `which += ":" + TaskState.Name(` 状态更新事件再把状态名带上,看得出流里的先后顺序。
- `def old_03() -> None:` 用 0.3 的老格式直接发一次:方法名 `message/send`、角色 `user`、每个 Part 带 `kind`。
- `"kind": "message"` 0.3 的消息要写 `kind`,1.0 删掉了。兼容开关打开时,服务端按这个老格式也能解析。
- `async def main() -> None:` 依次跑 JSON-RPC 非流式、REST 非流式、JSON-RPC 流式,最后再发一次老格式。

</div>

```text
JSONRPC    streaming=False -> 收到 1 个响应:['task']
HTTP+JSON  streaming=False -> 收到 1 个响应:['task']
JSONRPC    streaming=True  -> 收到 4 个响应:['task', 'status_update:WORKING', 'artifact_update', 'status_update:COMPLETED']
```

JSON-RPC 和 REST 拿到的是同一个任务对象,语义完全一样,差别只在怎么发(一个是 POST 到 `/rpc` 带方法名,一个是 `POST /rest/message:send`)。开了流式,同一次请求变成四个事件:先是 `task`,然后 `WORKING`,然后产出物,最后 `COMPLETED`,这就是第 1 步执行器里四个 `await` 在线上的样子。最后一行是 0.3 老格式:同一个服务端,回的是 `kind: task`、`state: completed`(小写),这是兼容模式替老客户端翻译的结果。

### v1.0 比 0.3 改了什么

下面这张表是对着官方的 `docs/whats-new-v1.md`(1.0.1 标签)整理的,挑了迁移时最容易出错的几项:

| 方面 | 0.3 | 1.0 |
| --- | --- | --- |
| 操作名 | `message/send`、`tasks/get`、`tasks/cancel` | `SendMessage`、`GetTask`、`CancelTask`;新增 `ListTasks` |
| 枚举值 | `"working"`、`"user"` | `"TASK_STATE_WORKING"`、`"ROLE_USER"` |
| Part 的类型 | 每个 Part 带 `kind` 字段 | 删掉 `kind`,看有哪个成员(`text`、`data`…) |
| 名片里的接口 | `preferredTransport` + `additionalInterfaces` | 合成 `supportedInterfaces` 数组,每项带 `protocolBinding` 和 `protocolVersion` |
| 协议版本 | 名片顶层有 `protocolVersion` | 挪到每个接口上 |
| 扩展名片 | 顶层 `supportsAuthenticatedExtendedCard`,方法 `agent/getAuthenticatedExtendedCard` | `capabilities.extendedAgentCard`,方法 `GetExtendedAgentCard` |
| 流事件 | 状态更新事件带 `final` 字段表示结束 | 删掉 `final`,由传输层自己的流关闭机制表示结束 |
| ID | 有些操作用 `tasks/{id}` 这种复合 ID | 一律是普通 ID,用独立字段传 |
| REST 路径 | `/v1/message:send` | 去掉 `/v1` 前缀 |
| 多租户 | 没有 | 请求里有 `tenant` 字段,接口上可以写默认租户 |
| OAuth 流程 | 含隐式、密码模式 | 去掉这两个,加 Device Code 和 `pkce_required` |
| 名片签名 | 没有标准做法 | JWS + RFC 8785 规范化 |

对你写代码影响最大的是前五行:字符串对不上就是 400 或者「方法不存在」。我的建议是,新项目直接按 1.0 写,只有要接老服务时才开兼容模式,并且对着名片里的 `protocolVersion` 判断对面是哪个版本,别猜。

还有一条规范里的小矛盾,是我读规范时看到的:6.4 节版本协商错误的示例用的是 `application/problem+json` 格式,11.6 节却规定 HTTP 绑定的错误用 `google.rpc.Status` 格式。遇到这种情况以规定性的章节(11.6)为准,示例只是示例。我没有去核对 1.0.1 之后的修订有没有统一。

## 第 4 步:身份与信任

```python
# agent-zero-lab/part10/a2a/finance_secure.py
"""带鉴权的对账 Agent:Bearer token 认「谁在调」,metadata 里的 onBehalfOf 说「替哪个客户调」。
环境变量 DELEGATION=strict 时,才按 onBehalfOf 校验发票归属。"""
import os

import uvicorn
from google.protobuf.json_format import MessageToDict
from a2a.helpers import get_message_text, new_data_part, new_task_from_user_message, new_text_message
from a2a.server.agent_execution import AgentExecutor, RequestContext
from a2a.server.events import EventQueue
from a2a.server.request_handlers import DefaultRequestHandler
from a2a.server.routes import create_agent_card_routes, create_jsonrpc_routes
from a2a.server.tasks import InMemoryTaskStore, TaskUpdater
from a2a.types import (
    AgentCapabilities, AgentCard, AgentInterface, AgentSkill, HTTPAuthSecurityScheme,
    SecurityRequirement, SecurityScheme, StringList,
)
from starlette.applications import Starlette
from starlette.authentication import AuthCredentials, AuthenticationBackend, AuthenticationError, SimpleUser
from starlette.middleware import Middleware
from starlette.middleware.authentication import AuthenticationMiddleware
from starlette.responses import PlainTextResponse

from part10.a2a.finance_server import INVOICE

PORT = 9103
STRICT = os.environ.get("DELEGATION") == "strict"
# 测试用的假 token,只在本机这个演示里有意义,不对应任何真实系统。
TOKENS = {"test-token-supportpilot": "supportpilot", "test-token-legal-agent": "legal-agent"}
INVOICE_OWNER = {"INV-0042-03": "C-0042", "INV-0077-01": "C-0077"}  # 发票属于哪个客户


class BearerBackend(AuthenticationBackend):
    async def authenticate(self, conn):  # type: ignore[no-untyped-def]
        if conn.url.path == "/.well-known/agent-card.json":
            return None  # 公开名片不要求登录
        header = conn.headers.get("authorization", "")
        user = TOKENS.get(header.removeprefix("Bearer ")) if header.startswith("Bearer ") else None
        if user is None:
            raise AuthenticationError("bad token")
        return AuthCredentials(["authenticated"]), SimpleUser(user)


def deny_anonymous(conn, exc):  # type: ignore[no-untyped-def]
    return PlainTextResponse("missing or invalid bearer token", status_code=401)


class SecureFinanceExecutor(AgentExecutor):
    async def execute(self, context: RequestContext, event_queue: EventQueue) -> None:
        assert context.message is not None
        task = context.current_task or new_task_from_user_message(context.message)
        if context.current_task is None:
            await event_queue.enqueue_event(task)
        updater = TaskUpdater(event_queue, task.id, task.context_id)
        caller = context.call_context.user.user_name
        on_behalf_of = str(MessageToDict(context.message.metadata).get("onBehalfOf", ""))
        hit = INVOICE.search(get_message_text(context.message))
        if hit is None:
            await updater.requires_input(new_text_message("请提供发票号"))
            return
        invoice = hit.group()
        print(f"[server] caller={caller} onBehalfOf={on_behalf_of or '-'} invoice={invoice}", flush=True)
        if STRICT and INVOICE_OWNER.get(invoice) != on_behalf_of:
            await updater.reject(new_text_message("这张发票不属于 onBehalfOf 指定的客户,或没有指定客户"))
            return
        await updater.add_artifact(parts=[new_data_part({"invoice": invoice, "owner": INVOICE_OWNER.get(invoice), "finding": "重复扣款"})])
        await updater.complete()

    async def cancel(self, context: RequestContext, event_queue: EventQueue) -> None:
        raise NotImplementedError


def build_card() -> AgentCard:
    return AgentCard(
        name="Finance Reconcile Agent (secured)",
        description="需要 Bearer token 的对账 Agent",
        version="0.2.0",
        default_input_modes=["text/plain"],
        default_output_modes=["application/json"],
        capabilities=AgentCapabilities(streaming=False),
        supported_interfaces=[AgentInterface(protocol_binding="JSONRPC", url=f"http://127.0.0.1:{PORT}/", protocol_version="1.0")],
        skills=[AgentSkill(id="reconcile_invoice", name="发票对账", description="按发票号对账", tags=["finance"])],
        security_schemes={"bearer": SecurityScheme(http_auth_security_scheme=HTTPAuthSecurityScheme(scheme="Bearer"))},
        security_requirements=[SecurityRequirement(schemes={"bearer": StringList()})],
    )


def build_app() -> Starlette:
    card = build_card()
    handler = DefaultRequestHandler(agent_executor=SecureFinanceExecutor(), task_store=InMemoryTaskStore(), agent_card=card)
    routes = [*create_agent_card_routes(card), *create_jsonrpc_routes(handler, "/")]
    return Starlette(
        routes=routes,
        middleware=[Middleware(AuthenticationMiddleware, backend=BearerBackend(), on_error=deny_anonymous)],
    )


if __name__ == "__main__":
    uvicorn.run(build_app(), host="127.0.0.1", port=PORT, log_level="warning")
```

<div class="line-notes">

- `STRICT = os.environ.get("DELEGATION") == "strict"` 一个开关,先跑不校验归属的版本,再跑校验的版本,对比着看。
- `TOKENS = {"test-token-supportpilot": "supportpilot"` 两个写死的假 token,对应两个调用方:SupportPilot 服务和一个法务 Agent。真实系统里 token 来自 OAuth 服务器,这里只是为了本地能跑。
- `INVOICE_OWNER = {"INV-0042-03": "C-0042"` 每张发票属于哪个客户。后面的越权演示靠它。
- `class BearerBackend(AuthenticationBackend):` Starlette 的鉴权后端:每个请求先过它,它决定「这是谁」。
- `if conn.url.path == "/.well-known/agent-card.json":` 公开名片不要求登录,否则调用方没法知道该怎么登录。
- `raise AuthenticationError("bad token")` 没带或者带错 token 就抛异常。我第一版写的是 `return None`,结果没 token 的请求照样进来了(Starlette 里返回 `None` 表示「匿名用户」而不是「拒绝」),POST 上来拿到 200。必须抛异常,配合 `on_error` 才会变成 401。
- `return AuthCredentials(["authenticated"]), SimpleUser(user)` 认证通过:返回权限列表和用户对象。SDK 会把这个用户的名字放进 `context.call_context.user.user_name`。
- `def deny_anonymous(conn, exc):` 认证失败时返回什么:401 加一句文字。
- `caller = context.call_context.user.user_name` 执行器里知道是谁在调:`supportpilot` 或者 `legal-agent`。
- `MessageToDict(context.message.metadata).get("onBehalfOf", "")` 消息的 `metadata` 是 protobuf 的 `Struct`,不能直接 `.get`。我第一版写的就是 `context.message.metadata.get(...)`,服务端抛 `AttributeError: get`,SDK 把它包成 `-32603 Internal error` 返回。`MessageToDict` 先转成普通字典。**`onBehalfOf` 是我们自己约定的字段名,A2A 规范没有规定怎么传最终用户的身份。**
- `if STRICT and INVOICE_OWNER.get(invoice) != on_behalf_of:` 严格模式才校验:这张发票属于谁,必须等于「替谁办事」。
- `await updater.reject(` 校验不过就把任务状态设成 `REJECTED`,附一句原因。对方没出错,只是「这活我不接」。
- `security_schemes={"bearer": SecurityScheme(` 名片里声明:本服务用 HTTP Bearer 鉴权。`security_requirements` 再声明「调用时必须满足 bearer」。
- `Middleware(AuthenticationMiddleware, backend=BearerBackend(), on_error=deny_anonymous)` 把鉴权挂到整个应用上。

```python
    body = {"jsonrpc": "2.0", "id": 1, "method": method, "params": params}

    if on_behalf_of:
        msg["metadata"] = {"onBehalfOf": on_behalf_of}
    return {"message": msg}

        r = await rpc(http, {"A2A-Version": "1.0"}, "SendMessage", message("INV-0042-03"))
        print("1. 没带 token:", r.status_code, r.text)

        print("2. SupportPilot 建任务:", task["id"][:8], task["status"]["state"])
        r = await rpc(http, SUPPORTPILOT, "GetTask", {"id": task["id"]})
        print("   SupportPilot 自己查:", r.json()["result"]["status"]["state"])
```

第 3 行才是真正的坑。SupportPilot 带着合法的 token(身份没问题),声称在替客户 C-0042 办事,却去问 C-0077 的发票,服务端照给了,`owner: C-0077` 明晃晃摆在结果里。这就是 **confused deputy**(被糊弄的代理人):服务端只认「谁在调」(SupportPilot 服务),不认「替谁调」,于是调用方拿到了它本来不该看的数据。真实场景里 SupportPilot 可能被一个恶意客户的提示词注入,让它「顺便也查一下这个发票号」,协议层的鉴权对此完全无感。

### 给 Agent Card 签名

还剩一个问题:你怎么知道自己下载的那张名片没被人改过?比如一个中间人把 `skills` 里的描述改成「也可以直接转账」,调用方的大模型读了就可能照做。1.0 规范给了标准做法:用 JWS(JSON Web Signature,一种把签名和被签内容打包在一起的格式,[Day 84](/blog/agent-zero/day-084-auth-2/) 讲的 JWT 就是它的一种特例,同样是 `header.payload.signature` 三段)给名片签名。但是 JSON 的字段顺序、空格都可能变,直接签字节会不稳定,所以签之前要按 RFC 8785(JSON Canonicalization Scheme,JSON 规范化方案)把 JSON 变成唯一的标准形式。

安装一个依赖,再写脚本:

```bash
uv add pyjwt cryptography
```

```python
# agent-zero-lab/part10/a2a/card_signing.py
"""给 Agent Card 签名、验签、篡改后再验。密钥是这次运行现生成的测试密钥,不要往里打钱,也别拿去干别的。"""
import base64
import json

from a2a.types import AgentCard
from a2a.utils.signing import (
    NoSignatureError,
    ProtectedHeader,
    SignatureVerificationError,
    create_agent_card_signer,
    create_signature_verifier,
)
from cryptography.hazmat.primitives import serialization
from google.protobuf.json_format import MessageToDict, ParseDict
from cryptography.hazmat.primitives.asymmetric import ec

from part10.a2a.finance_server import build_card

key = ec.generate_private_key(ec.SECP256R1())
private_pem = key.private_bytes(
    serialization.Encoding.PEM, serialization.PrivateFormat.PKCS8, serialization.NoEncryption()
)
public_pem = key.public_key().public_bytes(
    serialization.Encoding.PEM, serialization.PublicFormat.SubjectPublicKeyInfo
)

header: ProtectedHeader = {"alg": "ES256", "kid": "finance-test-key-1", "jku": None, "typ": "JOSE"}
sign = create_agent_card_signer(private_pem, header)
verify = create_signature_verifier(lambda kid, jku: public_pem, algorithms=["ES256"])

card = sign(build_card())
sig = card.signatures[0]

print("protected 头:", json.loads(base64.urlsafe_b64decode(sig.protected + "==")))
print("signature 前 20 位:", sig.signature[:20], "...")

verify(card)
print("1. 原样验签: 通过")

# 模拟中间人把技能描述改了一个字,然后拿同一份 signatures 去验
tampered = AgentCard()
tampered.CopyFrom(card)
tampered.skills[0].description = tampered.skills[0].description + "(也可以直接转账)"
try:
    verify(tampered)
except SignatureVerificationError as e:
    print("2. 改了技能描述后验签:", type(e).__name__, "-", e)

# 字段顺序不同、JSON 空格不同的同一张名片,规范化(RFC 8785)之后字节一样,应该照样通过

shuffled = {k: as_dict[k] for k in reversed(list(as_dict))}  # 顶层字段倒过来排
text = json.dumps(shuffled, ensure_ascii=False, indent=4)  # 缩进也换掉
reordered = ParseDict(json.loads(text), AgentCard())
verify(reordered)
print("3. 字段倒序、缩进改过的同一张名片: 通过 | 顶层字段顺序:", list(shuffled)[:3], "...")

    verify(build_card())
except NoSignatureError as e:
    print("4. 没签名的名片:", type(e).__name__, "-", e)

other_pub = other.public_key().public_bytes(serialization.Encoding.PEM, serialization.PublicFormat.SubjectPublicKeyInfo)
try:
    create_signature_verifier(lambda kid, jku: other_pub, algorithms=["ES256"])(card)
except SignatureVerificationError as e:
    print("5. 用别人的公钥验:", type(e).__name__, "-", e)
```

<div class="line-notes">

- `key = ec.generate_private_key(ec.SECP256R1())` 现场生成一把一次性的测试密钥(ES256 用的椭圆曲线 P-256)。这是测试密钥,只在这个脚本的内存里,不保存、不打印,不要拿它做任何别的事。
- `private_pem = key.private_bytes(` 把私钥导出成 PEM 格式(一段 `-----BEGIN PRIVATE KEY-----` 开头的文本),签名函数要的就是这种。
- `public_pem = key.public_key().public_bytes(` 导出公钥,验签的人只需要它。
- `header: ProtectedHeader = {"alg": "ES256"` JWS 的头:`alg` 是算法,`kid` 是密钥编号,方便验证方挑对的公钥。`jku` 是公钥集合的下载地址,这里不用,写 `None`。
- `sign = create_agent_card_signer(private_pem, header)` SDK 提供的签名器工厂:给它私钥和头,得到一个「拿名片、返回带签名的名片」的函数。
- `verify = create_signature_verifier(lambda kid, jku: public_pem, algorithms=["ES256"])` 验签器工厂。第一个参数告诉它「按 `kid` 和 `jku` 去哪里取公钥」,这里直接返回;`algorithms` 只允许 ES256,防止攻击者在头里改成 `none` 之类的弱算法。
- `card = sign(build_card())` 先造名片再签,签名会追加到名片的 `signatures` 里。
- `print("protected 头:", json.loads(base64.urlsafe_b64decode(sig.protected + "==")))` 签名头本身是 base64url 编码的 JSON,解开能看到 `alg`、`kid`。末尾补 `==` 是因为 base64 要求长度是 4 的倍数。
- `verify(card)` 原样验签,通过就静默返回,失败才抛异常。
- `tampered.skills[0].description = ` 模拟中间人改了一个技能描述。名片在内存里被改,但 `signatures` 原样带着。
- `except SignatureVerificationError as e:` 改过的名片验签失败,抛 `InvalidSignaturesError`。
- `shuffled = {k: as_dict[k] for k in reversed(list(as_dict))}` 把名片的顶层字段倒着排一遍。
- `text = json.dumps(shuffled, ensure_ascii=False, indent=4)` 再换成缩进四格的格式。内容一个字没变,字节完全不同。
- `reordered = ParseDict(json.loads(text), AgentCard())` 再解析回名片对象。这一步证明签名对**规范化后的内容**有效,和字段顺序、空格无关。
- `except NoSignatureError as e:` 没签名的名片,验签器单独报 `NoSignatureError`。
- `other = ec.generate_private_key(ec.SECP256R1())` 再生成一把别人的密钥,模拟「用错公钥验」。

五条输出对应五种情况。原样验签通过;改了一个字就不通过;字段倒序、缩进换掉但内容没变,照样通过(规范化的作用);没签名的名片会得到专门的错误;用别人的公钥验也不通过。

签名**只能证明「这张名片的内容没被改,且是持有这把私钥的人签的」,不能证明「持有私钥的人是你想找的那个公司」**。验证方拿到的公钥从哪来,才是信任的根:如果公钥是从名片同一个域名下载的,攻击者控制了域名就控制了公钥,签名形同虚设。所以 `key_provider` 那个函数里,生产环境应该查你自己维护的信任名单或者对方公司事先给你的公钥,而不是随手去 `jku` 地址下载。

最后说一件和签名无关但同样重要的事:另一个 Agent 返回的文本和产出物,对你来说就是**不可信的外部内容**,和网页一样可能带提示词注入([Day 403](/blog/agent-zero/day-403-injection-1/) 会系统讲)。不要把它直接拼进你的系统提示词,不要让它直接触发你这边的写操作。能用结构化的 `data` Part 就别用自由文本,并且在你这边校验字段。

**练习 1:让对账 Agent 支持取消。** 第 1 步的执行器 `cancel` 直接抛异常,所以 `CancelTask` 会失败。写一个 `SlowExecutor`:`execute` 里先 `start_work`,然后睡 30 秒假装干活;`cancel` 里把任务状态改成 `CANCELED`。写一个调用方:用 `returnImmediately: true` 发消息、立刻拿到任务、过一会儿查状态、取消、再取消一次,观察每一步的状态。要求全程在进程内跑,不开端口(用 `httpx.ASGITransport` 把客户端直接连到应用上)。

<details><summary>参考答案</summary>

```python
# agent-zero-lab/part10/a2a/ex616_cancel.py
"""练习 1:让对账 Agent 支持取消。慢任务 + return_immediately + CancelTask,全程在进程内(不开端口)。"""
import asyncio
import uuid

import httpx
from a2a.helpers import new_task_from_user_message, new_text_message
from a2a.server.agent_execution import AgentExecutor, RequestContext
from a2a.server.events import EventQueue
from a2a.server.request_handlers import DefaultRequestHandler
from a2a.server.routes import create_agent_card_routes, create_jsonrpc_routes
from a2a.server.tasks import InMemoryTaskStore, TaskUpdater
from starlette.applications import Starlette

from part10.a2a.finance_server import build_card


class SlowExecutor(AgentExecutor):
    async def execute(self, context: RequestContext, event_queue: EventQueue) -> None:
        assert context.message is not None
        task = context.current_task or new_task_from_user_message(context.message)
        if context.current_task is None:
            await event_queue.enqueue_event(task)
        updater = TaskUpdater(event_queue, task.id, task.context_id)
        await updater.start_work(new_text_message("慢慢对账中"))
        await asyncio.sleep(30)  # 如果没被取消,会在这里睡 30 秒
        await updater.complete()

    async def cancel(self, context: RequestContext, event_queue: EventQueue) -> None:
        assert context.task_id and context.context_id
        await TaskUpdater(event_queue, context.task_id, context.context_id).cancel(new_text_message("已按调用方要求取消"))


def build_app() -> Starlette:
    card = build_card()
    handler = DefaultRequestHandler(agent_executor=SlowExecutor(), task_store=InMemoryTaskStore(), agent_card=card)
    return Starlette(routes=[*create_agent_card_routes(card), *create_jsonrpc_routes(handler, "/")])


async def call(http: httpx.AsyncClient, method: str, params: dict) -> dict:
    body = {"jsonrpc": "2.0", "id": 1, "method": method, "params": params}
    return (await http.post("/", json=body, headers={"A2A-Version": "1.0"})).json()


async def main() -> None:
    transport = httpx.ASGITransport(app=build_app())
    async with httpx.AsyncClient(transport=transport, base_url="http://test") as http:
        msg = {"messageId": str(uuid.uuid4()), "role": "ROLE_USER", "parts": [{"text": "核对 INV-0042-03"}]}
        r = await call(http, "SendMessage", {"message": msg, "configuration": {"returnImmediately": True}})
        task = r["result"]["task"]
        print("立即返回:", task["status"]["state"])
        await asyncio.sleep(0.3)
        print("查一下:", (await call(http, "GetTask", {"id": task["id"]}))["result"]["status"]["state"])
        r = await call(http, "CancelTask", {"id": task["id"]})
        print("取消后:", r["result"]["status"]["state"], "|", r["result"]["status"]["message"]["parts"][0]["text"])
        r = await call(http, "CancelTask", {"id": task["id"]})
        print("再取消一次:", r["error"]["message"][:60], "|", r["error"]["data"][0]["reason"])


asyncio.run(main())
```

<div class="line-notes">

- `class SlowExecutor(AgentExecutor):` 和第 1 步结构一样,只是工作很慢。
- `await updater.start_work(new_text_message("慢慢对账中"))` 先把状态改成 working,让调用方看得到「在干活」。
- `await asyncio.sleep(30)` 如果没被取消,会在这里睡 30 秒。取消时 SDK 会取消这个协程,所以这行之后的 `complete` 不会执行。
- `async def cancel(` 取消钩子:SDK 在收到 `CancelTask` 时调它。
- `assert context.task_id and context.context_id` 取消时没有新消息,只有任务 id 和 contextId。
- `.cancel(new_text_message("已按调用方要求取消"))` `TaskUpdater.cancel` 发出 `TASK_STATE_CANCELED` 这个终态,并带一句说明。
- `transport = httpx.ASGITransport(app=build_app())` 让 `httpx` 不走网络,直接把请求交给 Starlette 应用处理。这样练习里不用开端口,也不用开两个窗口。
- `"configuration": {"returnImmediately": True}` 请求里的配置:建好任务立刻返回,不等任务结束。
- `print("立即返回:", task["status"]["state"])` 代入实跑:状态是 `SUBMITTED`,服务端刚收下,还没来得及开工。
- `r = await call(http, "CancelTask", {"id": task["id"]})` 取消。
- `r["error"]["data"][0]["reason"]` 再取消一次得到的错误原因在 `data[0].reason` 里,代入实跑是 `TASK_NOT_CANCELABLE`。

</div>

```text
立即返回: TASK_STATE_SUBMITTED
查一下: TASK_STATE_WORKING
取消后: TASK_STATE_CANCELED | 已按调用方要求取消
再取消一次: Task cannot be canceled | TASK_NOT_CANCELABLE
```

**练习 3:给别人家的名片做体检。** 你的 SupportPilot 要接入第三方的 Agent,从网上拿到的名片是不可信的 JSON。写 `lint_card(card: dict) -> list[str]`,返回问题清单:发现是 0.3 老格式(顶层有 `protocolVersion`、`preferredTransport`、`additionalInterfaces`、`supportsAuthenticatedExtendedCard`)、接口里绑定名不在三种已知值里、接口没写 `protocolVersion`、非本机地址用 `http://`、技能 id 重复或没有技能、没声明鉴权、没签名。用三张名片(合格的、0.3 的、马虎的)验证。

<details><summary>参考答案</summary>

```python
# agent-zero-lab/part10/a2a/ex616_card_lint.py
"""练习 3:给别人家的 Agent Card 做体检。输入是从网上拿到的 JSON,不信任它。"""
from typing import Any

KNOWN_BINDINGS = {"JSONRPC", "GRPC", "HTTP+JSON"}
OLD_03_FIELDS = ("protocolVersion", "preferredTransport", "additionalInterfaces", "supportsAuthenticatedExtendedCard")


def lint_card(card: dict[str, Any]) -> list[str]:
    problems: list[str] = []
    old = [f for f in OLD_03_FIELDS if f in card]
    if old:
        problems.append(f"这是 0.3 格式的名片(带 {', '.join(old)}),按 1.0 解析会出错")
    ifaces = card.get("supportedInterfaces", [])
    if not ifaces and not old:
        problems.append("supportedInterfaces 是空的,没人知道去哪调它")
    for i in ifaces:
        if i.get("protocolBinding") not in KNOWN_BINDINGS:
            problems.append(f"不认识的绑定 {i.get('protocolBinding')!r}")
        if not i.get("protocolVersion"):
            problems.append(f"{i.get('url')} 没写 protocolVersion(1.0 里它挪到了每个接口上)")
        if str(i.get("url", "")).startswith("http://") and "127.0.0.1" not in i["url"] and "localhost" not in i["url"]:
            problems.append(f"{i['url']} 不是 https,token 会明文走网络")
    skills = card.get("skills", [])
    ids = [s.get("id") for s in skills]
    if len(ids) != len(set(ids)):
        problems.append("skills 里有重复的 id")
    if not skills:
        problems.append("没有任何 skill,调用方没法判断它能干什么")
    if not card.get("securitySchemes") and not card.get("securityRequirements"):
        problems.append("没声明任何鉴权方式,要么是公开服务,要么是忘了写")
    if not card.get("signatures"):
        problems.append("名片没签名,无法证明它是主人发的(不签不算错,但要知道这一点)")
    return problems


GOOD = {
    "supportedInterfaces": [{"url": "https://finance.example.com/a2a", "protocolBinding": "JSONRPC", "protocolVersion": "1.0"}],
    "skills": [{"id": "reconcile_invoice"}],
    "securitySchemes": {"bearer": {"httpAuthSecurityScheme": {"scheme": "Bearer"}}},
    "signatures": [{"protected": "x", "signature": "y"}],
}
OLD = {"protocolVersion": "0.3.0", "preferredTransport": "JSONRPC", "url": "https://x.example.com/", "skills": [{"id": "a"}, {"id": "a"}]}
SLOPPY = {"supportedInterfaces": [{"url": "http://agents.example.org/a2a", "protocolBinding": "jsonrpc"}], "skills": []}

for name, card in [("GOOD", GOOD), ("OLD", OLD), ("SLOPPY", SLOPPY)]:
    print(f"== {name}")
    for p in lint_card(card) or ["没发现问题"]:
        print("  -", p)
```

<div class="line-notes">

- `KNOWN_BINDINGS = {"JSONRPC", "GRPC", "HTTP+JSON"}` 规范里官方支持的三种绑定名,注意大小写:协议绑定名是区分大小写的开放字符串,`jsonrpc` 不等于 `JSONRPC`。
- `OLD_03_FIELDS = (` 0.3 名片里有、1.0 里没有的顶层字段。
- `old = [f for f in OLD_03_FIELDS if f in card]` 找出名片里出现了哪几个老字段。
- `if not ifaces and not old:` 既没有新式接口数组、也不是老格式,才算「没人知道去哪调」;老格式的名片接口信息在别的字段里,单独报一条「0.3 格式」就够了。
- `if i.get("protocolBinding") not in KNOWN_BINDINGS:` `.get` 而不是 `[...]`:不可信的 JSON 可能缺字段,不能让体检函数自己先崩。
- `if not i.get("protocolVersion"):` 1.0 里版本写在每个接口上,漏了就没法判断对面说的是哪个版本。
- `and "127.0.0.1" not in i["url"] and "localhost" not in i["url"]` 本机地址允许 http,方便演示;其他地址用 http 就要提醒,因为 Bearer token 会明文走网络。
- `if len(ids) != len(set(ids)):` 集合去重后长度变短,说明有重复 id。
- `SLOPPY = {` 马虎的名片:绑定名小写、没版本、用 http、没技能、没鉴权。

</div>

```text
== GOOD
  - 没发现问题
== OLD
  - 这是 0.3 格式的名片(带 protocolVersion, preferredTransport),按 1.0 解析会出错
```

## 名词解释

| 名词 | 意思 |
| --- | --- |
| Agent Card | Agent 的名片,一个 JSON 文档,放在域名下 `/.well-known/agent-card.json`,写名字、技能、在哪个 URL 用哪种绑定调用、怎么鉴权 |
| Task | 一次委托的单位,有 id、状态、消息历史和产出物 |
| Message | 一来一回的一条消息,`role` 是 `ROLE_USER` 或 `ROLE_AGENT`,记录沟通过程 |
| Artifact | 任务的交付物,和 Message 的区别是它是结果,不是聊天 |
| Part | 内容的最小单位:`text`、`raw`、`url`、`data` 四选一 |
| 传输绑定(protocol binding) | 同一套 A2A 操作用什么方式传:JSON-RPC、gRPC、HTTP+JSON(REST) |
| JSON-RPC | 一种「POST 一个带方法名的 JSON 到固定地址」的调用约定,A2A 的默认绑定 |
| gRPC | Google 的二进制 RPC 协议,A2A 的第二种绑定,今天没实跑 |
| `A2A-Version` | 客户端每次请求带的头,值是主次版本号;没带当 0.3 |
| `AgentExecutor` | `a2a-sdk` 里你要实现的类,负责「收到消息后往外发哪些事件」 |
| `TaskUpdater` | SDK 的小助手,把状态变化和产出物翻译成事件 |
| SSE | Server-Sent Events,服务端往客户端单向推事件的 HTTP 机制,A2A 的流式靠它 |
| Bearer token | 放在 `Authorization: Bearer ...` 头里的凭证,谁拿着谁就是那个身份 |
| confused deputy | 被糊弄的代理人:服务端只认调用方身份,调用方拿自己的合法身份去办用户不该办的事 |
| JWS | JSON Web Signature,把签名和被签内容打包成一串的格式,A2A 用它给名片签名 |
| RFC 8785(JCS) | JSON 规范化方案,让「同样内容」的 JSON 变成唯一的字节串,签名才稳定 |
| PEM | 一种把密钥写成文本的格式,以 `-----BEGIN ...-----` 开头 |
| protobuf | Google 的数据定义语言,A2A 的权威数据定义 `a2a.proto` 就是 protobuf 写的 |

## 常见误区

**以为协议会替你做授权。** A2A 只让名片声明「我用 Bearer / OAuth」,校验是 HTTP 层的事,而且「替谁办事」连字段都没定。今天第 3 条输出已经演示了:身份对、数据错。

**认证后端里 `return None` 当拒绝。** Starlette 里返回 `None` 是「匿名用户」,请求照样往下走,我第一版就这么放进来了一个没 token 的 POST。要抛 `AuthenticationError`,并配 `on_error` 返回 401。

**新客户端忘了带 `A2A-Version`。** 没头当 0.3,在只开 1.0 的服务上得到「0.3 不支持」,看着像服务端问题。

**把 `onBehalfOf` 当成 A2A 标准字段。** 它是我们自己放进 `metadata` 里的约定,换一家 Agent 可能叫别的名字,甚至根本不看。跨公司用要提前和对方约定。

**签名通过就认为名片可信。** 签名只证明内容没被改、是私钥持有者签的。公钥从哪来才是信任的根,别从名片同一个域名下载公钥来验名片。

**不可信 JSON 用 `[...]` 直接取字段。** 练习 3 里用 `.get`,因为对方的名片可能缺字段,体检函数不能自己先崩。

**数字字段以为原样回来。** `1200` 经过协议的 `data` Part 变成 `1200.0`,金额用字符串。

**把 protobuf 的 `Struct` 当字典用。** `context.message.metadata.get(...)` 会抛 `AttributeError: get`,先 `MessageToDict`。

**往一个终态任务里补消息。** 练习 1 里取消之后再取消得到 `TASK_NOT_CANCELABLE`,想再来一次要开新任务。

## 自测

**1. A2A 的五个核心对象是什么?Message 和 Artifact 怎么分工?**

<details><summary>答案</summary>

Agent Card、Task、Message、Artifact、Part。名片是入口,任务是一次委托的容器,Message 记录沟通过程(反问、进度说明),Artifact 放交付结果,Part 是 Message 和 Artifact 共用的最小内容单位(`text`、`raw`、`url`、`data` 四选一)。交付结果放 Artifact,调用方不用从聊天记录里捞。

</details>

**2. 你的客户端调一个只支持 A2A 1.0 的服务,忘了带 `A2A-Version` 头,会发生什么?为什么?**

<details><summary>答案</summary>

规范规定没有这个头的话服务端按 0.3 处理。服务端只开了 1.0,所以返回 `VERSION_NOT_SUPPORTED`,报错信息里写的是「0.3 不支持」。看起来像服务端坏了,其实是客户端没带头。修法是每个请求都带 `A2A-Version: 1.0`(只写主次版本号)。

</details>

**3. 从 0.3 迁到 1.0,至少说出四处不兼容改动。**

<details><summary>答案</summary>

操作名从 `message/send` 变成 `SendMessage`;枚举值从 `"working"`、`"user"` 变成 `TASK_STATE_WORKING`、`ROLE_USER`;Part 删掉了 `kind` 字段;名片里的 `preferredTransport` 和 `additionalInterfaces` 合并成 `supportedInterfaces`,`protocolVersion` 挪到每个接口上;流事件里的 `final` 字段删掉;REST 路径去掉 `/v1`。还有 OAuth 去掉了隐式和密码模式、新增多租户 `tenant` 字段。

</details>

**4. SupportPilot 带着合法 token 去问财务 Agent 别的客户的发票,协议层的鉴权拦得住吗?应该怎么防?**

<details><summary>答案</summary>

拦不住。Bearer 鉴权只证明「调用的是 SupportPilot 这个服务」,不管「它替谁办事」,这就是 confused deputy。要把最终用户的身份和权限范围一起传下去(A2A 没有标准字段,需要和对方约定,比如放进 `metadata`),由被调用方按用户维度再校验一次,比如这张发票是不是属于这个客户,不是就 `REJECTED`。校验必须放在被调用方,调用方可能被提示词注入。

</details>

**5. 面试题:Agent Card 签名能解决什么问题?解决不了什么?**

<details><summary>答案</summary>

能解决:名片在传输和缓存过程中被篡改(比如技能描述被改成诱导性文字),验签就会失败。流程是先按 RFC 8785 规范化 JSON,再用 JWS 签名,验证方用公钥验。解决不了:签名只证明「内容没被改、是私钥持有者签的」,不证明私钥持有者就是你想找的那家公司。公钥从哪来才是信任根,如果公钥来自名片同一个域名,攻击者控制了域名就能自己签。所以验证方应该用事先从可信渠道拿到的公钥或信任名单。另外名片签名是可选的(规范用的是 MAY)。

</details>

**6. 为什么第 4 步里 `legal-agent` 拿同一个任务 id 查任务,得到的是 `TASK_NOT_FOUND` 而不是「无权限」?**

<details><summary>答案</summary>

规范要求服务端只返回对调用者可见的任务。SDK 的任务库默认按调用方用户名分开存,别人的任务对你来说就是不存在。返回「无权限」会泄露「这个 id 存在」,返回「没找到」就探测不出来。

</details>
